# 0.7.4a — HTML export render hotfix (dead module-nav buttons)

## Summary

P0: on a real run the report rendered but every module-nav button was dead, stuck on Overview. Cause: html_export filled the template with a SEQUENCE of str.replace() calls; project/backlog.json + project/build_history.json contain the literal token __CRYPTO_JSON_PLACEHOLDER__ in a note, so once projectPlanData was embedded the later replace() spliced the crypto JSON object into the middle of that JS string literal -> SyntaxError -> the whole inline <script> never ran -> no event listeners. Fix: utils/html_export._fill_template does one left-to-right pass (single re alternation, longest key first, function replacement) so inserted content is never re-scanned; run_html_export calls it once for all eight sentinels. _script_json unchanged.

Every embedded payload in a real render round-trips through json.loads; the sentinel token survives as data inside projectPlanData without expansion.
- **privacy_gate**: PASS / 0 on a clean tree.
- **real_env**: REAL_ENV_VALIDATED 2026-08-30 - the product owner regenerated the report on the corporate laptop from a full checkpoint run; all six modules and every tab work, no dead buttons.
