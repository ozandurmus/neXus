# distributed_endpoint_lock — DEV.3.2 - Distributed per-endpoint lock and cross-process admission (Postgres)

## Summary

User-approved contract implemented: CollectionCoordinator now delegates every admission decision to a CoordinatorBackend (utils/coordinator_backend.py); the default InMemoryCoordinatorBackend is the prior single-process logic moved verbatim (plus two incidental bug fixes: dead _endpoint_locks removed, budget_snapshot() undercounting above capacity 1 fixed). New opt-in PostgresCoordinatorBackend (SECURITYEXPERT_COORDINATOR_BACKEND=postgres) gives the per-endpoint exclusion and per-vendor budget a cross-process equivalent via session-level pg_advisory_lock held on a dedicated per-job connection (released by the server itself if the connection dies -- no TTL, no heartbeat), HMAC-derived lock keys so no device identity reaches Postgres, and a fail-closed startup preflight (verify_postgres_backend_ready) that detects a transaction-pooling proxy before use. main.py wires backend selection with a clean parser.error on failure and gates the scheduler read-evaluate-write cycle behind a scheduler-wide advisory lock on the Postgres backend. Concurrency budget value unchanged at 1; no collector/transport/command change.
