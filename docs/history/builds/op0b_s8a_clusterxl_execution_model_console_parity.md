# op0b_s8a_clusterxl_execution_model_console_parity — OP.0b S8-A - CP persistent Expert-shell execution model, real output shapes, and CLI/Operator-Console readiness parity (ClusterXL, real environment)

## Summary

The live S8-A ClusterXL campaign proved the CP preflight's remote execution primitive was wrong (one non-interactive exec channel per read, each dispatched through the Gaia CLI wrapper, so the five bare Expert reads never executed) and corrected it to one persistent Expert shell per member with deterministic nonce/exit-status framing and 0.3 s inter-command pacing; three real output shapes (fw stat table, cphaprob -a if annotated rows, cphaprob -ia list healthy sentence) and the A8 count wording were then recognised, and the operator report is regenerated from the same canonical readiness record the CLI prints, closing the fresh-CLI != Operator-Console defect without persisting a snapshot. Accepted by the PO on the real pair: 8/8 reads success, four checks PASS, remaining INSUFFICIENT_EVIDENCE only on the unresolved D-V7b/D-F3 decisions, and the Operator Console showing the identical seven checks and the fresh ClusterXL mode.
