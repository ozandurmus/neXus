# discovery_fixture_shape_drift — Fix hand-authored discovery_ui.json fixture to match the real builder shape

## Summary

tests/fixtures/uitest/build_fixture.py's discovery_ui() previously used hand-guessed field names (entity_id/collection_mode/deferred/last_transition_reason for entities; scope/started_at/finished_at for coordinator jobs) instead of the real utils.discovery_capability_ui._entity_row()/_coordinator_section()/_scheduler_section() shape (canonical_id/shell_type/planned_mode/plan_allowed/plan_reason_code/evidence_plane/transition_reason; workflow_scope/provenance/reason; workflow/interval_minutes). Because render_uitest.py injects this file via a monkeypatch that bypasses the real builder, the mismatch was invisible to every prior render-harness check -- Shell/Planned mode/Allowed/Reason and every coordinator-job-table column silently rendered undefined on the real UI since 0.7.6. Regenerated with the correct field names, also fixing two scenarios that could not occur under the real plan_collection() logic (a DISCOVERED+deferred_lifecycle entity, which the real planner never produces for a merely-DISCOVERED entity -- replaced with the real identity_failure_history rule). New regression test constructs an actual build_discovery_capability_payload() call and asserts the fixture's key sets match exactly, so this class of drift cannot silently recur; sanity-checked to fail against the pre-fix fixture and pass against the fix.

## Evidence

Net +1 from baseline 616, zero regressions.
