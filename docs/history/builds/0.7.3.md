# 0.7.3 — CE.1 - User-Authored Compliance Check Engine (data-driven, evidence-only)

## Summary

The BackBox/Nipper model: a check is DATA (name + evidence source + expected pattern + verdict), matches -> compliant, else not - over ALREADY-collected evidence. No server, no new device command. New utils/compliance_check_pack.py (load_compliance_checks -> CompliancePack from data/state/compliance_checks.json, schema v1, fail-closed; mirrors control_assignment.py): x_-prefixed check ids, a hand-written selector grammar NS('.'SEGMENT)* over namespaces {current_configuration, unified, crypto_facts, alignment} (no eval / no dep), a fixed 14-operator assertion set, evidence.steps[] with combine all|any, anchored regex <=512 chars behind a complexity linter + eval-time timeout, mode enforced|advisory, verdict on_pass/on_fail/on_no_evidence; a 'remediation' key is rejected (reserved for the write-capable future, CE.4). New utils/compliance_check_engine.py (resolve_source / apply_select / apply_assertion / evaluate_check, all pure; a path that can't be walked -> None -> on_no_evidence for every operator, never an inferred PASS; regex timeout -> step inconclusive; redacted_selector blanks [attr=value] filter values). compliance_posture: _subject_user_checks appends to subject.extended_controls (control_class user_check, advisory, pack, check_steps, redacted evidence_fields); _scoring_rows drops advisory rows from subject status + fleet counts + compliance_overview (which now extends all_ids / by_framework / severity with enforced user checks); applies_to miss -> assignment.not_assigned; new top-level check_packs (counts + pack_id only). control_assignment.load_control_assignments gains extra_known_ids so an include/exclude/waiver can target x_ ids. UI: 'user-defined' + 'advisory' badges on the control card, source-pack + per-step expected/observed lines in the 0.7.2 Explain panel (pattern expected shown as 'redacted'). Arbitrary user command strings are never executed. No certification claim.
