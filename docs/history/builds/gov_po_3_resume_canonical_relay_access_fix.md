# gov_po_3_resume_canonical_relay_access_fix — GOV.PO.3 -- resume canonical-relay access fix: --add-dir the canonical relay directory on every engineer spawn

## Summary

Closes the finding recorded in relay/NXS-LOCAL-0012's SESSION_CLOSE (`next`): a resumed engineer session (`orchestrator start`'s `--resume` path) could not read/write the canonical relay file outside its own worktree, while a fresh dispatch could -- blocking every future interrupted/resumed movement from completing autonomously (GOV_PO_3_APPROVED_MOVEMENT_ORCHESTRATION.md section 3.7's own recovery design). Root cause (AC-2, confirmed live, not assumed): with `--permission-prompts none` a Read/Edit/Write-tool call to a path outside the worktree has no approval surface, is auto-denied, and stays denied for the rest of the session with no retries; a fresh dispatch only ever appeared to work because it happened to route relay access through Bash-invoked `scripts/local_relay.py`, which this per-tool directory allowlist does not gate -- nothing guaranteed a resumed session would route the same way. Fix (AC-3): `scripts/orchestrator.py::_spawn_engineer` now passes `--add-dir <canonical_relay_dir>` identically for a fresh dispatch and a resume, so access no longer depends on which tool a session happens to pick.
