# op0b_s7_s6_test_order_isolation — OP.0b S7/S6 test-order isolation -- fix the module-rebind state leak

## Summary

tests/test_op0b_s7_readiness_v2.py::test_evaluator_performs_no_socket_io_and_imports_no_collector popped checkpoint.preflight_collector / panorama.preflight_collector out of sys.modules without restoring them, so any later `import panorama.preflight_collector as pc` (S6's collector tests) rebound to a fresh module object while S6's already-imported collect_member kept resolving api_post/get_direct_system_info/get_firewall_api_key against the original module dict, silently defeating S6's own patches and issuing real HTTP calls when S7 ran first. Fixed at the source with a save/restore try/finally around the same test; added a direct regression test proving the restoration (mirroring the frontend-rendering shared-state-leak guard precedent). Test-infrastructure only, no product code changed. In passing, also fixed (PO-authorized, relay/NXS-LOCAL-0016 seq 2-3, "authorize narrow interpreter-resolution fix to the merge-lock re-validation hook"): scripts/nexus_engineer_tool_gate.py's merge-lock re-validation subprocess calls used sys.executable directly, which resolved to a pytest-less system python3 in this session (a worktree checkout has no .venv of its own -- every worktree shares the one .venv next to the main checkout). New _resolve_interpreter()/_validation_commands() locate the shared .venv via `git rev-parse --git-common-dir` (stable across every worktree), falling back to sys.executable only if no .venv is found. Narrow, scoped to that one call site per the PO's authorization; nothing else in the hook touched.
