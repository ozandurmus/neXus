# operator_console_job_engine — Operator Console -- CON.2 job engine and read-class actions

## Summary

Implemented docs/history/phase/CON_2_CONSOLE_JOB_ENGINE_READ_ACTIONS.md against the frozen contract, after C-D3 (Provenance.CONSOLE vs reusing 'manual') was put to the product owner and resolved to add 'console' per the on-file recommendation. utils/collection_executor.py gained workflow_argv() (C2-2), promoted out of application/workflows/maintenance.py's _scheduler_workflow_argv, which is now a one-line wrapper over it -- the scheduler and the console job runner share one argv construction path. utils/coordinator_backend.py gained Provenance.CONSOLE = 'console' (C2-3); the required consumer audit found every consumer (Job.to_manifest_dict, RunContext.set_job_metadata, both InMemory/Postgres coordinator backends' free-text provenance column, the discovery/coordinator UI payload's job list, static/discovery_ui.js's rendering) already stores/echoes provenance as an unvalidated free string, so this was purely additive -- no schema or consumer change needed anywhere. utils/evidence_backend.py gained a sixth storage concern, ConsoleJobBackend (filesystem default + opt-in PostgreSQL, same abstraction shape as DEV.3.3's five), for durable job records under data_root/state/console_jobs, wired into verify_evidence_backend_ready()'s startup preflight. New console/registry.py (JOB_REGISTRY -- seven closed job types per C2-1, including cp_gaia_backup declared but refused per C2-6), console/jobs.py (ConsoleJobStore: C2-9 idempotency via a durable idempotency_key index, C2-5 crash recovery via sweep_orphaned_running(), forbidden fields excluded by construction -- JobRecord simply has no such field), console/runner.py (single-worker FIFO executor per C2-7; calls main.main() exactly as the scheduler's _evaluate_and_dispatch_due_workflows does and nothing else -- AC-2). console/app.py gained POST /api/jobs, GET /api/jobs, GET /api/jobs/{job_id}, GET /api/jobs/{job_id}/events (SSE, C2-10 -- job-record state transitions only, never collector output), GET /api/job-types; create_app()'s new job_store/runner parameters are optional (auto-constructed against an ephemeral in-memory coordinator when omitted) so CON.1's existing route-table test fixture and any read-only-only caller keep working unmodified. application/cli.py's --console branch now also calls services.build_collection_services() before run_console, so the console process holds one RuntimeCollectionServices for its whole lifetime -- passed to every job the runner executes, giving the same admission-state continuity across jobs that the scheduler already has across its own dispatch loop. static/console_actions.js gained the action surface in templates/console.html's Discovery module: job-type buttons (an operational-write type always renders BLOCKED per C2-6, never a button that would 409 on click), a recent-jobs table, and a manual SSE reader built on fetch()+ReadableStream rather than the native EventSource API, which cannot carry the Authorization bearer header CON.1's auth model requires.

## Risks forward

Real-environment validation is owed before this phase advances past AUTOMATED_VALIDATED: a watched run on the corporate laptop where a read-class action triggered from the console reaches a real device and produces the artifact an equivalent CLI run would -- hardware-gated, not an engineering task, no new code needed. The provenance change (C2-3) was the widest-blast-radius item in this phase per the contract's own risk callout; the audit found it genuinely additive, but any future consumer that starts validating provenance against a fixed set (rather than storing it as free text) must add 'console' to that set. static/console_actions.js's SSE reader is hand-rolled (fetch()+ReadableStream, no native EventSource) specifically because EventSource cannot carry a bearer header under CON.1's cookieless auth model -- worth remembering if a later phase is tempted to switch back to EventSource for convenience. C-D4..C-D8 remain open, product-owner/security calls blocking CON.3 onward.
