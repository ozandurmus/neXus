# op2_c1_cp_clusterxl_member_session — OP.2.C follow-up - real ClusterXLMemberSession over the validated per-member Expert session

## Summary

Implements checkpoint/clusterxl_member_session.py::RealClusterXLMemberSession, the first real implementation of the ClusterXLMemberSession Protocol the CP ClusterXL capability adapter (checkpoint/clusterxl_capability_adapter.py, OP.2.C) defines but deliberately ships no implementation of. Backed onto the existing, real-environment-validated per-member checkpoint/preflight_collector.py::MemberSession Expert-shell transport -- no new SSH client, no reconnect per command, no blind retry. read_role() reuses the already-approved A3 (cphaprob stat) / A5 (cphaprob -ia list) reads through MemberSession.run, preserving framing/exit-status handling/pacing; submit_admin_down()/submit_admin_up() issue exactly one of the two OP.2.1-approved literals (clusterXL_admin down / up, no -p) directly on the same shell, mapping to SubmissionConfirmation.CONFIRMED_NOT_SENT only when the command is positively proven never to have reached the device, and SUBMITTED_OR_AMBIGUOUS otherwise (OP.2.0 P6/P7). Neither the adapter contract, OP.2 lifecycle/authorization/readiness policy, nor preflight_collector.py were changed. Nothing outside tests/ references the new class -- CLASS 2 stays structurally unreachable (DenyAllAuthorizer unchanged, no taxonomy member, no production adapter_resolver).
