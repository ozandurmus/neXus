# gov_po_1_gate_1_command_safety_correction — GOV_PO_1_GATE_1 -- fix nexus_po_tool_gate.py false positives and enable packet emission

## Summary

Corrects scripts/nexus_po_tool_gate.py, found blocking the first real Phase A PLAN episode (gov_po_1_step_5_first_plan): its naive substring ban on '<'/'>'/';'/'|' rejected any command containing those characters even inside quoted data, blocking a standard git commit trailer's <email> and leaving no way to post the SESSION_START/SESSION_CLOSE relay packets section 5.1.1 requires (Write access is limited to 8 governance paths; there was no route to stage packet content without either Write outside those paths or banned shell redirection/piping). Replaces the substring check with shlex(punctuation_chars=True) tokenization, which reproduces bash's actual distinction (a metacharacter embedded in a quoted argument stays data; the same character standalone is a real operator), keeps backtick/$( banned unconditionally since bash still executes those inside double quotes, converts the destructive-word bans (rm/mv/cp/sudo/chmod/curl/wget/ssh/main.py) from substrings to exact tokens (this also newly denies `find ... -exec rm ...`, which the substring form missed since 'rm' there is a genuine bare token), denies a raw embedded newline outright (bash's other statement separator), and adds one narrow, auditable scratch-write allowance (nexus_po_*.json/.txt directly under a recognized system temp root, interactive form only) plus a matching restriction that --body-file may reference only that scratch pattern (closing an exfiltration path the prior test suite had accidentally asserted as allowed for an arbitrary filename). Also neutralizes an unrelated, real exposure found in the same review: the untracked .claude/settings.local.json on this workstation carried a blanket Bash(gh pr merge:*) allow rule that -- per section 6.2 item I3 -- would have applied uncontested to a PO session launched from the VS Code extension without --settings .claude/nexus-po.settings.json (the extension cannot pass that flag); emptied to permissions.allow: [] directly on the workstation, not part of this PR (untracked, gitignored, not repository state).
