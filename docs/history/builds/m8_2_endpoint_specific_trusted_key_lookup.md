# m8_2_endpoint_specific_trusted_key_lookup — M8.2 -- endpoint-specific local trusted-key lookup (mandatory trust-before-credential gate)

## Summary

New utils/cp_ssh_trust.py::lookup_trusted_host_key(endpoint, port) per the frozen M8 contract §4 step 1: a local-only, read-only, exact normalized-endpoint+port check against the same known_hosts source apply_strict_host_key_policy already reads, returning a typed TrustedKeyLookupResult (trusted/reason/immutable fingerprints mapping) instead of raising. No network/device contact, no key add/enroll/TOFU. Existing trust behavior (apply_strict_host_key_policy, load_trusted_host_keys) unchanged and re-verified. CORRECTION ROUND 1 (PO review): fingerprints made immutable (MappingProxyType); the fingerprint formatter consolidated into one shared, public utils/cp_ssh_trust.py::host_key_fingerprint() function that configuration/checkpoint_config_probe.py now imports and calls directly, replacing its own former private duplicate -- one implementation, not two independently-maintained copies that happened to agree.

## Risks forward

Pre-existing, unrelated to this build, reproduced identically with this change's edits git-stashed: tests/test_op0b_s8_p01_cp_ssh_trust_preflight_correction.py::TestStrictFailsClosedBeforeConnect::test_binary_garbage_fails_closed fails under the current local Paramiko version (REASON_NO_USABLE_HOST_KEYS instead of the expected REASON_TRUST_SOURCE_MALFORMED for a binary-garbage known_hosts file) -- a version-drift defect in apply_strict_host_key_policy/load_trusted_host_keys, untouched by this build; and tests/test_ci_workflow_fast_pr_regression.py fails to collect locally for a missing pyyaml dependency, unrelated to trust/identity work. Neither was introduced or fixed here and both should be triaged as their own, separate movement. This lookup only proves an entry exists in known_hosts for the exact endpoint/port at the moment of the call -- it is a point-in-time local read, not a live device confirmation; M8.3's producer must still perform the full trust-before-credential sequence (contract §4 steps 2-8) and must not treat a M8.2 hit as a substitute for the live handshake's own host-key verification. The endpoint/port normalization precondition (caller must pass already-normalized values) is documented but not independently re-validated inside lookup_trusted_host_key -- an un-normalized caller would silently miss a real entry (fail closed, safe direction) rather than silently match the wrong one; this is intentional (no second normalization authority per contract §2) but worth naming for M8.3/M8.4 callers. RESOLVED by correction round 1: fingerprints are now immutable (MappingProxyType) and the fingerprint format is a single shared implementation (host_key_fingerprint()) called by both this lookup and checkpoint_config_probe.py's live-connection path, not two implementations that could silently drift apart.
