## Summary

New utils/capability_state_resolver.py implements resolver stages 0-3 of docs/design/CAPABILITY_STATE_VOCABULARY_AND_PRESENTATION.md section 5, as pure typed-input functions with no I/O and no device contact: resolve_union_tag() decides the RESOLVED/OMITTED tag from D1 alone (Resolved and Omitted are structurally distinct dataclasses -- OMITTED carries only reason + optional diagnostic, never a None-filled capability output); evaluate_stage1()/evaluate_ri1_comparability() implement the CX1/RI-1/RI-2 contradiction-and-inconsistency gate, reusing utils.registry_evidence_reconciliation.detect_ri2 (M10.1) for RI-2 rather than reimplementing it, and the K1-K6 comparability precedence table for RI-1, in the frozen row order; resolve_primary_status() implements the twelve-rank primary ladder (ranks 0-11) first-match-wins; resolve_qualifiers() implements the seven independent CapabilityQualifier facets. The nine-value CapabilityState and seven-value CapabilityQualifier vocabularies are proven lexically disjoint from the console job lifecycle (X1), the OP.2 action-state vocabulary (X2) and utils.action_taxonomy tokens; to_wire() serializes only under the capability_state/capability_qualifiers keys the contract's namespacing rule (4.4) names.
