# op0b_s9_ui_authority_reconciliation — OP.0b S9 (remaining, broader scope) - UI authority reconciliation

## Summary

Retired the three remaining client-side/utility-side HA pairing and classification heuristics the bounded PAN-label slice (op0b_s9_pan_ha_label_authority_correction) left open, replacing each with the canonical backend field/derivation already computed -- for two of the three, already embedded unused in the same rendered page. static/inventory_ui.js's PAN pairing (panGroups/inferPairDescriptor applied to PAN device names, panoramaPairCompatible's VSYS/VR Jaccard similarity) and its cp_vsx_cluster hostname-token-overlap fallback now read failoverReadinessData.units -- utils.failover.assessment.compute_ha_readiness's own HaUnit derivation (_derive_pan_units / _derive_cp_units), consulting identity fields only (unit_id/unit_type/vendor/members/display_name), never verdict/checks/evidence, so no readiness authority moves into the UI. utils/merge.py's normalize_vsx no longer guesses a VSX physical device's cluster from a NAME-1/NAME-2 hostname suffix; run_merge now builds a device->cluster_topology lookup from the already-loaded cp.json rows (checkpoint/cp_runner.py::enrich_cluster_topology's runtime VIP fingerprint) and copies the matching device's canonical cluster_topology onto the vsx.json row. utils/config_ui.py's _ha_header_evidence config-state fallback now recognizes only the literal yes/no PAN-OS XML API boolean tokens (matching the vocabulary utils.failover.assessment._derive_pan_units already treats as canonical for the same kind of field) instead of an independently invented on/off/true/false/1/0 tolerance no real device response ever emits.
