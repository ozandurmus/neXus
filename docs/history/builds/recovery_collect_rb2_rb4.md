## Summary

User directed: resolve D2, build RB.4, and build recovery collection under explicit constraints -- not inlined in main.py, selective per gateway, scheduler-integrated, mergeable with a future UI. D2 resolved 2026-08-30 (product owner approval, recorded in docs/design/BACKUP_AND_RECOVERY_ARCHITECTURE.md §13): PAN service account may hold superuser for device-state export only. New utils/recovery_collect.py is the single orchestration layer -- target selection (select_recovery_targets: 'all' or an explicit entity_id list including the VSX __vsid_ convention; an unresolvable id raises before any device is touched), a RecoveryCollector protocol for vendor dispatch, and run_recovery_collection routing every target through a caller-supplied admission hook so one gateway's failure never aborts the batch. panorama/panorama_recovery_collector.py implements PAN device-state export (contract §7.1, read class, gate-documented before this build) reusing panorama_runtime_runner.get_api_key/_tls_verify_setting verbatim with per-host API-key session reuse and no 403 retry. checkpoint/checkpoint_recovery_collector.py is a typed blocked stub (RecoveryCollectionBlockedError naming D3, unresolved -- CORRECTED during the main-merge on 2026-08-30: the P0 cp_device_interaction_safety audit itself closed 2026-08-25, before this build; D3 is the only real remaining blocker) so orchestration/store/admission wiring is already correct for CP once D3 is decided and the command gate signs off. utils/collection_executor.py: ALLOWLISTED_WORKFLOWS gains 'recovery-pan' (not 'recovery-cp'); ScheduledWorkflow gains an additive optional 'targets' field (schema version unchanged, every prior policy file's meaning preserved). main.py stays thin: --recovery-collect/--recovery-vendor/--recovery-gateways parse arguments and dispatch only; _scheduler_workflow_argv extended for recovery-pan. Separately, utils/recovery_validation.py (RB.4) implements the V1-V3 battery frozen in contract §4 and utils/recovery_store.revalidate_artifact wires it into the store (decrypt in memory only); main.py --recovery-validate gates on any individual check FAIL, not the top-line verdict alone, after a real bug was caught where a V2-only failure reported verdict=INTACT (V1 passed) and would have silently passed a naive gate.
