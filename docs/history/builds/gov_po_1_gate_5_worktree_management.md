# gov_po_1_gate_5_worktree_management — GOV_PO_1_GATE_5 -- allow git worktree add/list from interactive PO sessions

## Summary

Adds git worktree add (interactive form only, restricted) and git worktree list (both forms, read-only) to scripts/nexus_po_tool_gate.py, so the PO role can hand off a future engineering movement in an isolated physical checkout instead of sharing this session's single checkout -- Product Owner direction after two same-checkout collision risks were caught and avoided this session (gov_po_1_gate_3 vs m10_1; the paused gov_po_1_local_relay_watch_command vs gov_po_2_freeze_and_merge). git worktree add's base commit-ish must start with origin/, exactly mirroring the existing git merge origin/<ref> restriction, so no arbitrary local path, remote, or URL is ever reachable as a worktree base; a -b/-B branch name, when present, must start with feature/ (gov/po- stays reserved for the PO's own governance branch). git worktree remove/prune/move stay deliberately unallowlisted -- the PO role never destroys a worktree in this movement's scope.

## Risks forward

This movement adds worktree creation only, not the portability mechanic: relay/*.json's own Edit/Write path-matching stays anchored to the main checkout's cwd, so a relay file for a worktree-hosted movement is still authored in the main checkout and handed to the engineer by absolute path (or via a small premerge to origin/main first), per this movement's own SESSION_START sequencing note. A future movement should decide whether relay path-matching ever needs to become worktree-portable.
