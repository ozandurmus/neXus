## Summary

Fixes the live bug found 2026-09-08 while the Product Owner monitored five in-flight PRs (#127-#131): the GitHub Actions 'validation' workflow's Repository privacy gate (`python main.py --repository-privacy-check`) scanned the full working tree with no baseline and failed unconditionally on the same two pre-existing, already-accepted findings (project/build_history.json, relay/NXS-LOCAL-0003-local-relay-watch-command.json) that relay/NXS-LOCAL-0014 already taught the local pre-push hook to treat as pre-existing debt. Extracted that hook's content-fingerprint baseline-comparison primitives (finding_fingerprint/finding_key/baseline_finding_keys) out of scripts/nexus_engineer_tool_gate.py into utils/repository_privacy.py so both the local hook and the CI-facing entry point (application/workflows/maintenance.py::repository_privacy_check, reached via a new `--privacy-baseline-ref` CLI flag) share one implementation. The CI workflow now checks out full history (fetch-depth: 0), explicitly fetches origin/main, and passes `--privacy-baseline-ref origin/main` to both `validate` (pull_request) and `full-regression` (workflow_dispatch) job invocations. Omitting the flag reproduces the pre-fix behavior exactly (every finding fails); a genuinely new finding still fails with the flag present.
