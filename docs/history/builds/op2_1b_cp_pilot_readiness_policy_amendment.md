# op2_1b_cp_pilot_readiness_policy_amendment — OP.2.1b - CP pilot readiness-policy amendment (D-V7b/D-F3/D-F2)

## Summary

Readiness-layer policy amendment (utils/failover/assessment.py, utils/failover/preflight_readiness.py) per explicit product-owner decision: preemption_known (Check Point only, D-V7b) and flap_history (both vendors, D-F3) are now a closed-list, exact-reason, deterministic 'advisory-exempt' set -- each check stays INSUFFICIENT_EVIDENCE, visible, with its exact existing reason, but that status no longer by itself blocks an otherwise-positive readiness verdict; PAN's preemption_known is deliberately NOT exempted since a supported read exists there. D-F2 (member skew) never gated a check -- its roll-up-level policy gate is simply retired (no threshold, ever); UNRESOLVED_POLICY_DECISIONS shrinks to {D-F1} only. No override, no operator control, no new verdict vocabulary; FAIL, identity/coherence failures, collection failures and any reason string outside the closed list still block exactly as before. Proves over a generated matrix that SAFE_TO_FAILOVER is now reachable for a CP ClusterXL entity given a fresh OP.0b preflight run where the other five stop-conditions genuinely pass, and never reachable for any other combination; OP.0a's stored-telemetry SAFE-unreachable invariant (AC-6) is untouched. No device contact, no vendor adapter, no taxonomy member, no change to OP.2.0/OP.2.1's own frozen text.
