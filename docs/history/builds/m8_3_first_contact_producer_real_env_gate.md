## Risks forward

Real-environment validation is NOT performed in this pass -- Product Owner authorization is separately required (contract §9, AI_START_HERE.md 'Real-environment procedure'). Exactly one bounded, read-only command is proposed for that gate: `py main.py --identity-first-contact <one enrolled device_id>`, targeting exactly one registry device_id, exercising the full trust -> credential -> RejectPolicy -> identity gate -> serial -> governed evidence -> relationship-write sequence, reporting only relationships/statuses (never raw endpoint/serial/fingerprint/username/credential/host-key values), verifying the newly created producing_run_ref is resolvable, and measuring the actually observable CP config evidence-retention lower bound/window the frozen contract §6/§9 needs before CONTRADICTORY_EVIDENCE detection can be judged buildable -- reporting UNKNOWN/INSUFFICIENT_EVIDENCE rather than inferring a duration if the real evidence does not establish one. Until that gate runs, M8.3 stays AUTOMATED_VALIDATED only and M8.4 (the M6 resolver consumption slice) must not begin -- per contract §9, M8.4 requires at least one real-environment-validated relationship from this producer. This build did not add admission-coordinator (utils.collection_executor) integration for the device-contact step, unlike the OP.0b S7.5 CP/PAN HA preflight entry points -- a deliberate scope decision (this is a narrow, manually-invoked, single-device CLI maintenance/bootstrap tool, the same category as --registry-enroll/--persistent-secret-material-check, not part of the scheduled/concurrent collection surface); if a future build wants concurrency protection here, that is its own bounded addition, not implied by this one. The _ELIGIBLE_REGISTRY_STATES=={'ENROLLED_UNVERIFIED'} gate is this build's own defensive addition (a DISABLED/RETIRED device should not be first-contacted) -- the frozen contract's §2 does not itself name a lifecycle-eligibility requirement, so this is a conservative interpretation, not a restated contract clause; it mirrors console/registry_targets.py's M6 eligibility set in spirit only (utils/ does not import console/). Three dissents remain open, unchanged from M8/M8.1/M8.2: operator_assertion, single-sourced identity evidence, deferred CONTRADICTORY_EVIDENCE detection.
