# m10_1_registry_evidence_reconciliation_projection — M10.1 -- registry <-> evidence reconciliation projection (D4 producer)

## Summary

New utils/registry_evidence_reconciliation.py implements the D4 registry<->evidence reconciliation projection: resolve_d4() derives one of the five frozen values (RECONCILED, EVIDENCE_ONLY, REGISTRY_ONLY, REGISTRY_DISABLED, RECONCILIATION_UNKNOWN) from already-classified registry and evidence sides, and detect_ri2() implements the RI-2 bounded-inconsistency check. Per RELAY_DECISION on ozandurmus/nexus-agent-relay#11 (2026-09-08): utils/device_registry.py's device_id and the merged evidence model's collector entity_id are different, non-comparable identifier spaces with no canonical id spanning both today, so this slice reads the registry only and treats the evidence side as EvidenceSide.UNRESOLVABLE everywhere -- never utils/device_identity_relationships.py (M8.1), whose mapping_scope is documented as prohibited for any purpose beyond CLASS_0_CP_CONFIG_TARGET_SELECTION_ONLY. REGISTRY_DISABLED is the one exception: it derives from the registry row alone (AC-5) and reports correctly even while the evidence side is unresolvable. No producer is wired to any resolver, UI, navigation or payload; the projection persists nothing new.
