# NXS-LOCAL-0342 — Backup and recovery microservice (ui2-backup) and 400GiB artefact vault

## Summary

Stood up ui2-backup with Check Point Gaia fail-closed SCP pull and a Palo Alto HTTPS XML API stream. Added the AST semantic deviation engine and the 400GiB artefact vault.

Correction recorded 2026-09-20 (NXS-LOCAL-0347): no independent ui2-backup microservice was delivered. The backup API is served by BackupController inside ui2-service, and the executors (BackupJobExecutor, BackupCapabilityExecutor) run inside ui2-worker, which already mounts the artefact-store PVC at /app/artefact-store. Live probe against the deployment: /api/v2/backups/policies and /api/v2/backups/deviations answer 403 and /backups answers 401, so the routes are mounted and gated; kubectl shows no ui2-backup object in the cluster. deploy/ui2/56-backup-deployment.yaml and 56-backup-service.yaml were removed: their args ['worker','backup'] fall through to the generic worker branch in Ui2WorkerMain (which branches only on 'configuration' and 'compliance'), and they carry no database or secret environment, so applying them would have crash-looped a second worker. Divergence reported, not reconciled: docs/design/ASTRA_BACKUP_ENGINE_ARCHITECTURE_REVIEW.md still describes an independent microservice on port 8086 with a dedicated ui2-backup-vault-pvc at /vault/recovery and ui2-service forwarding to it. That document carries no status line, so it is not implementation authority, but it and the implementation disagree and the Product Owner owns which one is meant to win.
