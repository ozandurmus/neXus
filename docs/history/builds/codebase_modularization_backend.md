# codebase_modularization_backend — Codebase modularization (main.py orchestration split) -- backend-half implementation

## Summary

Implemented docs/history/phase/CODEBASE_MODULARIZATION_BACKEND.md against the frozen contract. main.py (2,089 lines) reduced to a 47-line thin entry: main() is a one-line delegation to application.cli.run, plus the __main__ guard and re-exports of the F4 surface (7 contract names + _cp_stage_cooldown/_run_scheduler_once, both directly patched/called by existing tests). New application/ package: cli.py (build_parser / validate_modes / dispatch / run, Phase A verbatim), services.py (Phase C runtime foundation, the F6 bootstrap/runtime-config helpers, build_collection_services, the make_admitted/make_runtime_config closure factories), context.py (ApplicationContext dataclass for the ~15 former main() locals), workflows/{maintenance,recovery,checkpoint}.py per the frozen ownership table. Phase E (staged pipeline, RunContext lifecycle, degraded policy, the try/except/finally with cfg.clear_credentials()) moved as one unit into checkpoint.integration_checkpoint; its three F5 helpers stay nested inside that entrypoint (closing over the entrypoint's own parameters instead of main()'s, which satisfies the de-closure intent without spreading the Phase-E lazy-import cluster across module scope).

## Risks forward

A real pre-existing gap surfaced by the new AC-3 check: main.py's top-level 'from utils.config_storage import ...' was already pulling in lxml transitively (via utils/config_evidence.py) on every invocation, contradicting AI_START_HERE.md's documented lazy-import contract -- not introduced by this build, but only closeable once the code moved and became visible to a static check. Fixed in application/workflows/maintenance.py by moving that import into storage_analyze()/storage_deduplicate() (first use), zero output/behavior change. Two test files' source-string / monkeypatch-by-name checks could not stay byte-identical under AC-1's <=120-line main.py (a namespace/text-of-main.py assumption, not a behavior assertion) -- repointed to the new application/*.py locations, same class of mechanical repoint the frontend half applied to 16 tests; see the phase doc's Implementation deviations. Vendor-collector split (configuration/pan/, configuration/checkpoint/) stays out of scope, opens as its own feature-scoped entry if ever needed.
