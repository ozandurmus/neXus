# Check Point cluster VIP (role=cluster_virtual) has never been observed anywhere in the fleet

status: planned · target: 

Reported by the Product Owner: the Cluster VIP column reads empty for every Check Point cluster. Measured against the live database: 847 device_interface_address rows exist, all role='member', zero role='cluster_virtual', across every sampled cluster. CheckPointClusterVirtualInterfaceParser and its cphaprob -a -m if command are correctly wired into InventoryCapabilityExecutor and match Check Point's own 'Viewing Cluster Interfaces' documentation exactly. A live diagnostic log (vip_output_len) added and shipped this session proves the command itself returns zero bytes of output on every device tried; a cphaprob -a if trial without the -m flag also returned zero bytes on the same devices, so the flag is not the cause and that trial was reverted. Root cause is genuinely open: either this fleet's Check Point clusters do not configure per-interface virtual/VIP addressing (plausible if failover relies on something other than IP-based cluster virtual interfaces), or there is a session/shell-context issue specific to this one command that cphaprob stat and every other command in the same batched exec do not share. The next step needs either the Product Owner's own knowledge of how this fleet's clusters are actually configured, or a bounded, explicitly-authorized one-time inspection of the real cphaprob -a -m if output on one device -- not another blind syntax guess.
