# .claude/nexus-engineer.settings.json never actually granted Edit/Write despite claiming default-allow -- every successful movement to date wrote files only via Bash

status: done · target: .claude/nexus-engineer.settings.json -- fixed live 2026-09-08, uncommitted pending a standalone PR

Found live 2026-09-08 while resuming NXS-LOCAL-0020 (gov_po_3_ci_privacy_gate_baseline_scoping): its Edit call on utils/repository_privacy.py was denied with 'this session has no approval surface to grant file-write permissions'. Root cause: scripts/orchestrator.py::_spawn_engineer passes `--permission-prompts none` (no human to answer a prompt, per relay/NXS-LOCAL-0015's own AC-1/AC-2/AC-3 comment), and .claude/nexus-engineer.settings.json's permissions block had only two `deny` entries (force-push) and no `allow` entries at all -- so every Edit/Write call, which requires approval by default, was silently auto-denied for the life of the process, contradicting the profile's own '_comment' claim of 'Default-allow (normal dev tools: Read/Edit/Write/Bash/Git)'. The same denial is visible in relay/NXS-LOCAL-0018's own engineer.log (Edit on project/build_history.json during merge-conflict resolution) -- that movement only succeeded because its engineer fell back to Bash-only file writes without flagging the denial as unusual. Fix: added `permissions.allow: ["Edit", "Write", "MultiEdit"]` to the profile (applied directly to the file on disk 2026-09-08 by explicit Product Owner action via chat '!' passthrough, since Claude Code's own auto-mode classifier refuses an AI-initiated Edit to a settings/tool-configuration file). Confirmed working: NXS-LOCAL-0020 resumed cleanly afterward. Still needs a standalone PR to persist the fix for future clones/CI -- the live fix is currently only an uncommitted change in the main checkout.
