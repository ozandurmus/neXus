# Credential profile / enterprise vault abstraction

status: in_progress · target: 1.0 foundation

2026-09-09: reference-model slice landed -- utils/credential_profiles.py (CredentialProfile: name-only record, no secret field by construction; resolve_credential_profile() maps a profile name onto SECURITYEXPERT_CREDENTIAL_PROFILE_<NAME>_PRINCIPAL/_SECRET and reads them through the unmodified DEV.2.1/DEV.2.2 <VAR>_FILE > <VAR> source, utils.runtime_config_source.resolve_value -- no second credential-sourcing mechanism). Profile name format matches utils.device_registry's existing credential_ref shape. ResolvedCredential is unpersisted, redaction-registered via utils.logger.register_sensitive_value, and its repr/str never expose principal or secret. 17 targeted tests in tests/test_credential_profiles.py (resolution precedence, missing/malformed-name failure modes, no-secret-field structural checks, redaction, no persistence/logging side effects). Still open for a future 1.0 slice: the enterprise vault abstraction itself (this module *is* the reference model the vault would sit behind, per docs/design/PRODUCT_CONTROL_PLANE_ARCHITECTURE.md section 6) and wiring a profile name up through the PCP.1 Device Registry's already-existing credential_ref field to this resolver (deliberately out of scope here).

PO decision 2026-09-13: the store must hold BOTH a local account and a directory account, and the product must not care which -- UI2_0_C3B ROLE-1/ROLE-3 and UI2_0_B1_04B section 6 already model this as one opaque reference whose backing type the management plane verifies, not the product. The estate uses one directory account reached through RADIUS, LDAP or TACACS for both vendors, and the productised service account will also be a directory account, so two management-plane records may reference the same credential. Key-based authentication is supported as an option and never the default (PO_DECISION_RECORD_2026_09_13D SB-15): a key is its own identity, it changes management-plane audit attribution, its custody is a problem of its own, and on the Check Point plane it is in practice bound to a local account rather than a directory-authenticated one.
