# scripts/project_queue.py has no write path for roadmap now_next.now / current_build, so 'build add' cannot be used without violating GOV.ORCH.5/8

status: planned · target: A successor to scripts/project_queue.py gains a command that moves roadmap now_next.now/next and current_build in the same transaction as 'build add'

Found 2026-09-12 during the B1-1 draft-authority cleanup. project/README.md (GOV.ORCH.8) makes scripts/project_queue.py the only write path for project/build_history.json and project/roadmap.json, and AGENTS.md GOV.ORCH.5 forbids hand-editing either. But 'build add' inserts a newest-first build_history record without touching roadmap now_next.now or current_build, and utils.project_plan._cross_authority_warnings rule R1 requires now_next.now.build to equal the newest build_history record. Observed failure: tests/test_architecture_convergence.py::test_project_metadata_has_no_cross_authority_contradictions reported 'roadmap now_next.now.build (ui2_b1_01_skeleton_ci_docker) is not the newest build history record (...); one of the two is stale' immediately after a clean 'build add'. Consequence: an agent can only record a new build by hand-editing roadmap.json (forbidden) or by not recording it. This movement took the second path and recorded its evidence with 'build note' against the existing current build instead. Contradiction reported, not reconciled.

Fixed 2026-09-12: 'build add' now advances roadmap now_next.now/current_build in the same validated transaction as the build_history head insert, requires --advance-now, enforces the record_contract summary/status limits, re-renders QUEUE.md and regenerates docs/history/INDEX.md. Regression: tests/test_project_queue.py::test_build_add_leaves_no_cross_authority_contradiction.
