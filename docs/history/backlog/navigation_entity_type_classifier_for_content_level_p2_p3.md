M11 formalized D1/stage-0 as the sole render/not-render gate (AC-CS-2/AC-CS-25) but explicitly did not build content-level P2 (entity applicability) or P3 (evidence state) rendering -- e.g. a D-NAV13 NOT_APPLICABLE device tab (the ha_readiness capability's own worked example: 'a standalone firewall has no HA readiness', already populated in utils/capability_applicability.py's D2 table). Building it inside M11 would have been scope creep into a new identity/producer surface, which M11's own scope.out forbade touching. This movement built exactly that classifier (single-row device/VS drilldown classification, and multi-row grouped cluster/pair classification reusing the cluster_topology.group_id convention checkpoint/cp_runner.py::enrich_cluster_topology already writes, plus a pan_ha_runtime parameter for PAN HA state that unified.json itself never carries) and demonstrated its composition with resolve_d2/resolve_d3, but deliberately stopped there.
