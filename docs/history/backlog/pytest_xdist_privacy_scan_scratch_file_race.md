# tests/test_gov_po_3_ci_privacy_gate_baseline.py's transient scratch fixture can crash a concurrently-running full-repository privacy scan under pytest-xdist

status: planned · target: Test-infrastructure follow-up; discovered incidentally while validating dlp_scanner_prose_collision_in_frozen_records

Discovered 2026-09-09 (NXS-LOCAL-0042) as one of three failures in an otherwise-successful full one-shot regression: tests/test_nexus_engineer_tool_gate.py::test_ac1_live_bug_regression_against_real_repository_state failed with utils.repository_privacy.RepositoryPrivacyError: cannot safely inspect text candidate: scratch_ac6_synthetic_leak.md. That path is written and then removed by a fixture inside tests/test_gov_po_3_ci_privacy_gate_baseline.py (line ~192), transiently, at the repository root; under `pytest -n auto --dist worksteal` a concurrently-scheduled worker running test_ac1's real filesystem scan of ROOT can observe the file mid-existence and crash on its deliberately-bad encoding before the owning fixture deletes it. Confirmed as a pre-existing, order/parallelism-dependent flake unrelated to this movement's own change: re-running both test files together serially (`pytest tests/test_nexus_engineer_tool_gate.py::test_ac1_live_bug_regression_against_real_repository_state tests/test_gov_po_3_ci_privacy_gate_baseline.py`, no -n) passed 11/11; `git diff --stat` for this movement touches only tests/test_dev_0_5b_auth_consumer_canonical_config.py. Fix direction (not decided/implemented here, out of this movement's DLP-only scope): give the scratch fixture a non-ROOT-colliding location (e.g. a tmp_path-based scratch dir, or a name the privacy scan's own candidate filter structurally excludes) so no cross-test race is possible regardless of xdist scheduling.
