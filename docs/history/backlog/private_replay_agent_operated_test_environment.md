Objective: let a coding agent (Claude) drive real UI/menu/workflow testing against neXus to reproduce real customer-topology bugs, without the agent ever seeing real device identities, credentials or raw evidence content. FROZEN as of 2026-09-08 for Phase A only: PRIVATE_REPLAY (agent uses an immutable HMAC-pseudonymized dataset derived from a real collection, extending utils/support_bundle.py's existing Tokenizer) and SYNTHETIC_SCENARIO (agent uses fabricated edge cases -- stale peer, timeout, trust mismatch -- absent from the real environment). LIVE_PRIVATE (agent-triggered real collection via a trusted local execution service) is Phase B, deferred design only, not authorized by the freeze -- requires its own separate Product Owner authorization and explicit reconciliation with docs/AI_DEVELOPMENT_PROTOCOL.md's network-device command gate + utils/action_taxonomy.py before any dispatch.

This session's (2026-09-08) counter-review was accepted in full and folded into the frozen document: (1) offline-first sequencing (Phase A ships before any live-collection design is even authorized, not bundled with the exporter as originally proposed); (2) reuse of the existing AI-initiated-device-command gate rather than a parallel authorization mechanism; (3) isolation testing required from the agent's own actual tool perspective (Read/Bash/env-inspection/process-inspection against a dummy service with synthetic canaries), not just API-malformed-request testing.
