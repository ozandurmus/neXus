Driver: the BackBox exit (BACKUP_AND_RECOVERY_ARCHITECTURE.md section 2) needs an operator surface, not just a capability -- BackBox's daily value is seeing the fleet and acting on a row, which today requires the CLI. Central decision: do NOT make the exported report dynamic. The portable, shareable, action-free output/index.html is a product feature; the console is a SECOND delivery surface over the same engine, sharing one UI source tree (mode flag SECURITYEXPERT_MODE) and one orchestration core. Security boundary: the browser sends intent (a job_type resolved against a closed, source-resident registry plus entity ids validated against unified.json), never a device command, flag or argv fragment -- which is how this stays inside SERVER_PRODUCTIZATION_AND_MODULARIZATION_ARCHITECTURE.md's prohibitions on a generic REST wrapper and browser-supplied commands (that doc is amended with a section 7 reconciliation, prohibitions unrelaxed). The console adds exactly four things - an HTTP boundary, an auth boundary, a durable job record and one new provenance value - and no new device path: execution reuses main(argv, runtime_services, provenance) the way the scheduler already does (main.py:361), plus CollectionCoordinator admission and the 24h operational-write ledger unchanged.
