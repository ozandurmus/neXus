# scripts/local_relay.py append accepts a relative --file path that silently shadows the correct canonical relay file with a new local copy inside the engineer's own worktree

status: done · target: scripts/local_relay.py::_resolve_relay_file / append CLI -- observed live on NXS-LOCAL-0021 (orchestrator_interactive_dashboard_app), 2026-09-08

NXS-LOCAL-0021's engineer posted its AC-2 design-note RELAY_NOTE to a NEW file at <worktree>/relay/NXS-LOCAL-0021-orchestrator-interactive-dashboard-app.json instead of the canonical relay/ file the orchestrator spawned it against (env NEXUS_RELAY_FILE/NEXUS_CANONICAL_RELAY_DIR were set correctly at spawn time, per relay/NXS-LOCAL-0015's own --add-dir fix). Likely cause: `scripts/local_relay.py append`'s `--file` argument, when given a relative path, silently overrides the correct absolute env-var default and resolves relative to the engineer's cwd (the worktree root) per `_resolve_relay_file(explicit) -> explicit or env`, landing in a brand-new worktree-local relay/ file rather than erroring. The canonical relay file was left un-advanced (stuck at seq 1 SESSION_START, next_actor engineer) while the worktree's shadow copy silently accumulated the real conversation (seq 2 RELAY_NOTE, status AWAITING_PO) -- invisible to the PO/orchestrator until manually discovered and copied over by hand. Recovered manually this time (no lost content), but this is a real footgun: nothing currently stops a relative --file from creating a divergent shadow relay file, and the ENGINEER_PROMPT does not explicitly warn against passing --file at all when the environment default is already correct. Fix direction (not yet designed): reject or warn on a --file value that does not resolve to the same absolute path as NEXUS_RELAY_FILE when both are present, or resolve --file relative to NEXUS_CANONICAL_RELAY_DIR rather than cwd, or simply strengthen the ENGINEER_PROMPT to never pass --file explicitly when the env default is already set.

RESOLVED 2026-09-08 (NXS-LOCAL-0026): implemented reject-on-mismatch in `_cmd_append` -- when `NEXUS_RELAY_FILE` is set and an explicit `--file` is also given, append now refuses (EXIT_USAGE) unless `os.path.abspath(--file) == os.path.abspath(NEXUS_RELAY_FILE)`, instead of silently operating on the mismatched path. No `--file` (env default) and an absolute `--file` matching the env var are unchanged. Regression coverage added to tests/test_local_relay_protocol.py (the module's actual test file; the movement's own AC-3 named a not-yet-existing tests/test_local_relay.py) reproducing the exact NXS-LOCAL-0021 shape (NEXUS_RELAY_FILE/NEXUS_CANONICAL_RELAY_DIR set, relative --file that would previously resolve against cwd) plus a mismatch case and an env-unset passthrough case; also added an autouse env-clearing fixture to that test file since the ambient NEXUS_RELAY_FILE a real orchestrated engineer session exports was leaking into and breaking pre-existing tests once the mismatch check existed.
