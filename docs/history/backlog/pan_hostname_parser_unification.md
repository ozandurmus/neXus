# Unify the two independent PAN managed-device-discovery hostname parsers

status: done · target: Follow-up to OP.0a.P7

Closed: added panorama/pan_identity.py::parse_pan_managed_device_entry(), a single shared parser for one <devices><entry> element of the <show><devices><all/></devices></show> response (mirrors CP's utils.restore_readiness.resolve_entity_id precedent). panorama/panorama_runtime_runner.py::get_devices() and configuration/panorama_config_collector.py::get_devices() both now walk entries through this one function instead of two independent XML reads; each keeps only the keys it needs. No existing fixture exercised the two implementations' prior serial-extraction divergence (config_collector already stripped + fell back to the entry `name` attribute; panorama_runtime_runner did neither), so converging both onto that more defensive behavior changes no existing test's output -- proven by the pre-existing suite passing unchanged plus new characterization tests (tests/test_pan_hostname_parser_unification.py, and an added case in tests/test_phase0_5_final_panorama_management_ip.py) covering whitespace-padded serial/hostname, entry-name-attribute fallback, and a missing serial being dropped.
