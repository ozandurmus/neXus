AUTOMATED_VALIDATED 2026-09-09 (docs/design/COMPLIANCE_CHECK_ENGINE.md section 5, decision D8; relay/NXS-LOCAL-0037). Shipped: configuration/command_primitives.py -- a static registry (CommandGateReview dataclass carrying all 10 network-device-command-gate points per entry: reason, action_class_id, vendor_platform_shell_context, timeout_seconds, retry_count, max_frequency_per_endpoint_minutes, session_reuse, unsupported_behavior, secret_output_risk, safe_telemetry) admitted only through register_primitive(), which fails closed if the declared action_class_id is not utils.action_taxonomy.CLASS_0_READ, if the literal command text matches a write-command-marker denylist, or if the numeric gate fields are out of a sane range -- a defense-in-depth check atop the human review, independent of it. Two concrete, gate-reviewed proof primitives, one per major vendor, each reusing an already-controlled transport/command rather than opening a new credential path (diagnostic-path law): cp_gaia_show_version_all (Check Point, reuses configuration.checkpoint_config_probe._connect/_run_exec and the exact 'clish -c show version all' the 0.6.1A probe already gate-reviewed) and pan_show_system_info (Palo Alto, reuses panorama.panorama_runtime_runner.get_api_key/op_cmd/fix_host and the exact op command configuration/panorama_config_collector.py already issues). PrimitiveExecutionTracker enforces the design's 'once per device per run' admission (in-memory, not a durable ledger -- explicitly deferred to a future promotion past opt-in probe mode, mirroring RECOVERY_OPERATIONAL_WRITE_LEDGER.md's precedent); run_check_point_primitives/run_palo_alto_primitives each open exactly one session/API key per probe batch and reuse it across every admitted primitive against that endpoint (session-reuse gate rule, test-proven via call-count assertions on a mocked transport). Redaction is uniform and raw-evidence-law compliant: every primitive's redact() returns only {bytes, lines, fingerprint_sha256} over the exact output text -- never raw content -- discarded by the caller in the same function that captured it. Admission wiring: new main.py --compliance-probe (application/workflows/compliance.py), modelled on --cp-config-probe -- reuses checkpoint_config_probe._pick_targets() for Check Point target selection (no second target-selection policy for the same evidence question) and the first already-discovered Panorama-managed serial for Palo Alto (best effort; AC-4 only requires 'CP and/or PAN'), both admitted through the existing utils.collection_executor admission coordinator (vendor='checkpoint'/'paloalto', so the existing 1-per-vendor budget applies unchanged), writes a new local-only redacted evidence artifact (output/compliance_probe_<timestamp>.json, sensitivity LOCAL_OPERATOR_SENSITIVE_NOT_SHAREABLE), and is mutually exclusive with every other collection/render/maintenance mode. Engine wiring (the 'exposed to the engine only as source namespace primitive.<primitive_id>' invariant, proven not just declared): 'primitive' added to utils.compliance_check_pack.SOURCE_NAMESPACES; utils.compliance_posture.build_compliance_posture/_subject_user_checks/_subject_evidence gained an additive primitive_facts_by_subject parameter (byte-identical when omitted, mirroring the existing crypto_facts_by_subject shape/precedent exactly) so a check pack can reference primitive.<id>.<field> today. Deliberately NOT wired into any normal-run caller (html_export.py unchanged) -- primitives execute only under the opt-in probe, never a normal collection run, per design section 5's 'Opt-in first' and this movement's explicit scope (promotion beyond opt-in probe mode is out of scope). diagnostic_runbooks_read_only's own runbook-catalog implementation was NOT built here (shares this registry per its own backlog note; clear extension points only -- PRIMITIVE_REGISTRY/primitives_for_vendor/run_*_primitives are vendor-generic and take an explicit primitives= list).
