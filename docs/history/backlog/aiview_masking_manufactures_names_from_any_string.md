# The AIView pseudonymizer turns any non-blank string into a convincing hostname, so a fallback management address renders as a healthy device name and hides the data gap from the one persona the constitution mandates for verification

status: planned · target: TopologyNamePseudonymizer.computeDeviceName; interacts with discovery_lateral_join_drops_cluster_members

Found 2026-09-20 while reconciling two contradictory readings of the same inventory screen. computeDeviceName applies HMAC to whatever string it is given and formats the result as FW-XXXX-NN. It never checks that the input is a hostname, and maskDeviceName only short-circuits on null or blank. The device select resolves its display through coalesce(observed_hostname, dc.display_name, ep.address_ref), so when the discovery lateral join fails the third element applies and the value handed to the masker is a management address. Under a session without the replay viewer role the screen then shows a raw address with no model, which is what the Product Owner reported. Under aiview the same row shows a well-formed device name, which is what this session saw, and the two observers disagreed for hours over data that was identically broken in both cases. Consequences beyond this defect: the constitution makes aiview the mandatory persona for UI inspection, validation evidence and Product Owner sign-off, so a masking layer that can manufacture identity from a fallback value can certify a screen the unmasked product cannot serve. Any verification performed under aiview before this is fixed carries that caveat. The fix is not to weaken masking. A value that is not a hostname must not be pseudonymized into one: the masker should carry an explicit unknown rather than invent a name, and the display chain should not silently substitute an address for a name in the first place.

2026-11-11 fix: TopologyNamePseudonymizer no longer mints a device-style name for a non-hostname. isNotAHostname (blank, placeholder spellings, IPv4 with optional prefix length, anything containing a colon) returns the fixed gap word Unknown from maskDeviceName, maskManagedDeviceName and computeDeviceName; a new overload maskDeviceName(raw, cluster, deviceId, managementAddress) treats a name equal to the row's own management address as the same gap. Where only an opaque device ID is left (job-log targets with no recorded hostname) the masked projection now shows maskUnknownHost(id): UNKNOWN-HOST-<6 hex of a keyed HMAC>, stable per device, distinct per device, never an FW- name. The inventory hostname field passes its row's management_ip/address; the Logs estate dictionary, the Data Sanitizer known names and the diagnostic known names skip non-hostnames; isGap(masked) replaces the string compare at every caller. Identity law unchanged: nothing is cast or normalised beyond detecting an address shape. Remaining half of this item (the display chain coalesce(observed_hostname, display_name, address_ref) substituting an address for a name in the unmasked view) stays with discovery_lateral_join_drops_cluster_members.
