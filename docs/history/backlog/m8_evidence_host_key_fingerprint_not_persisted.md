# M8.4 finding: CP config evidence snapshot metadata carries no host-key fingerprint, so the M8 trust-currency check can never affirmatively pass against real M8.3 evidence

status: automated_validated · target: configuration/checkpoint_config_collector.py::_collect_host (the shared, 'existing unmodified' physical-host collection primitive both the bulk collector and the M8.3 producer reuse)

Discovered while implementing M8.4 (console/registry_targets.py's identity-translation currency checks, frozen M8 contract section 7): one required condition is 'the current trusted-key fingerprint for the live registry endpoint agrees with producing_run_ref's captured fingerprint.' _collect_host does capture a live host-key fingerprint (host_row['host_key_fingerprint'] = key_fp) but never persists it into the CP config evidence snapshot's extra_metadata (configuration/checkpoint_config_collector.py, the store.write_text_snapshot(...) call inside _collect_host) -- so no resolvable producing_run_ref evidence written by any real M8.3 run today carries a host_key_fingerprint field. M8.4's own check therefore fails closed (never a vacuous pass) for every real relationship until this is fixed -- proven and pinned by tests/test_m8_4_m6_resolver_consumption.py::TestCurrencyFailuresFoldToIdentityTranslationRequired::test_todays_real_m8_3_evidence_shape_has_no_fingerprint_and_fails_closed. Not fixed in M8.4 itself per that movement's own scope boundary ('do not modify the M8.3 producer unless a material correctness defect makes M8.4 impossible' -- M8.4's own resolver logic is fully correct and testable via fixture evidence that does carry the field; the gap is in the shared collector's evidence-write path, not in M8.3's or M8.4's own code, and touching the shared, unmodified _collect_host primitive deserves its own explicit review rather than a scope-expanding side effect here). Proposed minimal fix: add "host_key_fingerprint": host_row.get("host_key_fingerprint") to the extra_metadata dict _collect_host already passes to store.write_text_snapshot for the physical-host artifact (PHYSICAL_ARTIFACT_TYPE only -- do not add it to the VSX context artifact, which has no independent host-key handshake of its own). This value is a SHA256: fingerprint, not raw key material or a credential -- consistent with this repository's existing host_key_fingerprint format and the M8 contract's own privacy law (fingerprints are the one piece of trust evidence M8.2/M8.3 already treat as safe to carry, e.g. utils/cp_ssh_trust.py::TrustedKeyLookupResult.fingerprints). UPDATE 2026-09-07: fixed on branch m8-evidence-host-key-fingerprint-not-persisted -- host_key_fingerprint now flows into the physical-host store.write_text_snapshot(...) extra_metadata exactly as proposed above; VSX context evidence intentionally unchanged. See project/build_history.json's m8_evidence_host_key_fingerprint_not_persisted record for full evidence.
