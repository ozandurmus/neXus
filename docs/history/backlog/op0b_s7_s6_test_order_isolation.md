# OP.0b S7 readiness tests leak state into the S6 PAN preflight collector tests when run out of default order

status: automated_validated · target: OP.0b

AUTOMATED_VALIDATED 2026-09-08. Root cause confirmed exactly as hypothesized: tests/test_op0b_s7_readiness_v2.py::test_evaluator_performs_no_socket_io_and_imports_no_collector popped checkpoint.preflight_collector / panorama.preflight_collector out of sys.modules (to force a fresh, uncached import) and never restored them. When S6 ran afterward, its `import panorama.preflight_collector as pc` (inside `_collect`/`run_pan_preflight` call sites) rebound `pc` to a brand-new module object; `collect_member`, imported by tests/test_op0b_s6_pan_preflight_collector.py at file-collection time (i.e. against the ORIGINAL module object), kept resolving `api_post`/`get_direct_system_info`/`get_firewall_api_key` as globals against that original module dict, so S6's own `patch.object(pc, ...)` on the new module object never reached the real call sites -- real HTTP calls followed, confirmed via a real, hanging `requests` connection attempt to the test fixture's synthetic management-IP target during reproduction. Fix: the popped sys.modules entries are now saved and restored in a try/finally around the same test body -- no product code touched, no test reordering, no global conftest hack. New regression test test_evaluator_probe_restores_the_collector_modules_it_pops asserts the restoration directly (module identity before/after), mirroring the existing frontend-rendering shared-state-leak guard precedent (test_render_uitest_restores_the_builders_it_injects), so a future regression is caught locally instead of surfacing as 25 unrelated S6 failures. Verified both orders green: `pytest tests/test_op0b_s7_readiness_v2.py tests/test_op0b_s6_pan_preflight_collector.py` and the reverse, 110 passed each; each file alone unchanged in count (S7 69 incl. the 1 new test, S6 41).
