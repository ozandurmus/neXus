# Security Review — Script Execution Slice 2 (`lane/script-s2-v256-1119`)

## Verdict: **DO NOT SHIP**

The broker/execution-pod split (`ui2-script-runner` + per-run Kubernetes `Job` `script-run-<id>`, internal port `8086` key custody in `ui2-service`, `ui2_script_runner` DB role, V256) closes the core UID/environment/key-exposure flaw of 2026-11-18. However, **three P0 blockers** (an AIView unmasked-data + mutation bypass on `run_as = role:replay_viewer`, a deterministic first-ship bootstrap deadlock in `script_runner_db_login.py` / `module_deploy.py`, and broken `Origin` enforcement breaking every non-`GET` `nexus-cli` call with `401`) and **four P1 security/lifecycle defects** must be fixed before shipping.

---

## Scope Assessment Summary (by Review Dimension)

- **Tenant / pod isolation:** Execution pods run under `ui2-script-run` (`automountServiceAccountToken: false`, no `RoleBinding`), `uid/gid 20185` (distinct from image UID `185`), `readOnlyRootFilesystem: true`, `allowPrivilegeEscalation: false`, `capabilities.drop: [ALL]`, `RuntimeDefault` seccomp, `enableServiceLinks: false`, no `secretKeyRef`/`envFrom`/`hostPath`/PVC mounts, and seed `Secret`s mounted only in the `seed` `initContainer` (`0400`/`0500` in `/scratch`). Broker holds no store keys and spawns no processes (`ScriptRunnerModuleFenceTest`). Residual broker RBAC blast radius if the broker JVM itself were compromised is noted in **P2-11**.
- **Network egress of the run pod:** Default-deny `ui2-script-run-default-deny` (Ingress + Egress) plus per-run `NetworkPolicy` allowing `kube-dns:53` (UDP/TCP), `ui2-service:8080` (TCP), and TCP to run-start DNS-resolved `/32` and `/128` `ipBlock`s. However, `resolveEgress` enforces **no IP denylist** against internal cluster/pod/registry/node/external-DB/link-local addresses, permits DNS-based correlation bypass for enrolled device IPs, and leaves recursive `kube-dns:53` open on every run even when `egress = []` (**P1-5**).
- **Credential handling:** Store master keys stay exclusively in `ui2-service`. Per-run secrets travel over in-cluster HTTP (`ui2-service-internal:8086`) to the broker, into immutable Kubernetes `Secret`s (`script-run-<id>-s<n>`), into `/scratch` via `umask 077` + `chmod 0400` in `seed`, and into child env (`NEXUS_CRED_<ALIAS>_*`). Critical gaps: Kubernetes `Secret`s have no `ownerReferences`/TTL and strand plaintext credentials and write-only script bodies in etcd on broker crash/cancel (**P1-6**), and `/scratch` uses disk-backed `emptyDir` rather than `medium: Memory` (**P2-9**).
- **DB role privileges (`V256`):** `ui2_script_runner` cannot read `script`, `script_version`, `script_run`, `credentials`, `credential_references`, `sessions`, `audit_log`, or `backup_artefact` (proven on PostgreSQL 16 in `ScriptRunnerDatabaseRoleIntegrationTest`). Table-wide `UPDATE`/`DELETE` grants on `jobs`, `failover_*`, `endpoint_admission`, and `runtime_task_lease` remain un-scoped by RLS until `jobs.state` triggers become `SECURITY DEFINER` (**P2-11**).
- **Output masking and audit:** Broker masks full streams before 256 KiB truncation, drops partial lines at the 4 MiB log read cap, and `ui2-service` masks a second time; `GET /api/v2/scripts/runs/{runId}/output` is `role:operator`+ and audited. However, `output_tail` (up to 4 KiB — the complete output of most scripts) is returned **un-gated and un-audited** on `SCRIPT_READ` routes to `viewer` and `replay_viewer` (**P1-4**), and GNU `base64` 76-column line wrapping escapes masking for secrets $\ge 57$ bytes (**P2-12**).
- **Operator-input injection into Job spec:** Clean. All Kubernetes manifests are built as Java `Map` trees serialized via Jackson `ObjectMapper` (no YAML/JSON string interpolation); `kind` maps through a closed `switch` in [ScriptInterpreter.java:21-62](../../ui2/worker/src/main/java/com/securityexpert/nexus/ui2/worker/scriptrunner/ScriptInterpreter.java#L21-L62); object names pass strict `^script-run-[a-z0-9]([a-z0-9-]{0,48}[a-z0-9])?$` validation in [ScriptRunKubernetes.java:22-56](../../ui2/worker/src/main/java/com/securityexpert/nexus/ui2/worker/scriptrunner/ScriptRunKubernetes.java#L22-L56); and `credentials.env` single-quotes values (`'\''`) under validated `[A-Z][A-Z0-9_]*` aliases.
- **Resource limits / DoS:** CPU/memory (`1` / `1Gi`), `activeDeadlineSeconds`, and `emptyDir.sizeLimit` (`512Mi`) are set, but `script_output` has **no 30-day retention pruner** on the shared 10 GiB `ui2-report-store` PVC (**P1-7**), `runNow` lacks disabled-script and per-script in-flight guards (**P2-8**), and execution pods lack `ephemeral-storage` and `ulimit -u` PID caps (**P2-9**).

## Ranked Findings

### P0 — Must Fix Before Ship (Blockers)

#### P0-1: `run_as = role:replay_viewer` bypasses AIView masking (`IS_REPLAY_VIEWER_ATTRIBUTE`) and `machine`-session write blocks, exposing raw production data and mutating Packet Analysis routes
- **Location:** [RouteActionGate.java:117-123](../../ui2/service/src/main/java/com/securityexpert/nexus/ui2/service/security/RouteActionGate.java#L117-L123), [ScriptRunDispatchService.java:215-217](../../ui2/service/src/main/java/com/securityexpert/nexus/ui2/service/script/ScriptRunDispatchService.java#L215-L217), [ScriptExecutionJob.java:37-38](../../ui2/platform-core/src/main/java/com/securityexpert/nexus/ui2/platform/ScriptExecutionJob.java#L37-L38) (hidden in tests by `routeGate(gateChain, null, null)` at [ScriptSchedulerAndRunServiceTest.java:214-215](../../ui2/service/src/test/java/com/securityexpert/nexus/ui2/service/script/ScriptSchedulerAndRunServiceTest.java#L214-L215)).
- **Failure scenario:** `RoleToken.REPLAY_VIEWER` is in `RUN_AS_ALLOWLIST`. When a script executes with `run_as = role:replay_viewer`, `ScriptRunDispatchService.start` mints `actorFingerprint = "script_session:<scriptId>:<jobId>:role:replay_viewer"` via `sessions.createActive(...)` (`machine = false`). In production (`RbacConfiguration.java:106,117`), `RouteActionGate` has non-null `localIdentityResolver` and `localRoleTokenResolver`, so lines 117–121 evaluate **only** `localIdentityResolver.resolve(actorFingerprint)` — which returns `Optional.empty()` for `script_session:...` — and never call `gateChain.isReplayViewer(...)`. Consequently:
  1. `IS_REPLAY_VIEWER_ATTRIBUTE` is `false`, completely bypassing [PrivacyMaskingResponseBodyAdvice.java:113-124](../../ui2/service/src/main/java/com/securityexpert/nexus/ui2/service/privacy/PrivacyMaskingResponseBodyAdvice.java#L113-L124) and controller `isReplayViewer` guards: the script receives **unmasked raw production hostnames, management IPs, serials, policy rules, system logs, discovery runs, and `SECURITY_SCAN_SUMMARY_READ`** (including actions like `DISCOVERY_RUN_START`, `DEVICE_CONFIGURATION_COLLECT`, `FMG_DIAGNOSTIC_RUN`, `STATIC_ROUTE_PREVIEW`, and `SECURITY_SCAN_SUMMARY_READ` that even `role:operator` is denied).
  2. Because `session.machine()` is `false`, [GateChain.java:98-102](../../ui2/service/src/main/java/com/securityexpert/nexus/ui2/service/security/GateChain.java#L98-L102) skips the machine-session write gate, allowing a `role:replay_viewer` script to `DELETE` Packet Analysis cases/telemetry and `PUT` case topologies under `PACKET_ANALYSIS_RUN`.
- **Fix:**
  1. In `RouteActionGate.java:117-123`, when `identity.isEmpty()`, fall back to `gateChain.isReplayViewer(proceed.actorFingerprint())` (which evaluates RBAC for `RoleToken.REPLAY_VIEWER`, covering both `script_session:...:role:replay_viewer` and directory-bound replay viewers).
  2. In `ScriptRunDispatchService.java:215`, mint `role:replay_viewer` sessions with `sessions.createMachineActive(...)` (`machine = true`), or remove `RoleToken.REPLAY_VIEWER` from `RUN_AS_ALLOWLIST` if unprivileged read-only scripts only need `role:viewer`. Test `RouteActionGate` with non-null `LocalIdentityResolver`/`LocalRoleTokenResolver`.

#### P0-2: First-ship bootstrap deadlock between `script_runner_db_login.py`, `V256`, `ui2-service`, and `module_deploy.py`
- **Location:** [script_runner_db_login.py:54,76-79](../../tools/delivery/script_runner_db_login.py#L54-L79), [run_build.sh:32](../../deploy/ui2-image-build/run_build.sh#L32), [hosta_deploy.sh:36](../../tools/delivery/hosta_deploy.sh#L36), [61-script-runner-deployment.yaml:218-233](../../deploy/ui2/61-script-runner-deployment.yaml#L218-L233), [50-service-deployment.yaml:157-162](../../deploy/ui2/50-service-deployment.yaml#L157-L162).
- **Failure scenario:**
  - Running `script_runner_db_login.py db-login` **before** shipping V256 fails under `psql -v ON_ERROR_STOP=1` because `SELECT ui2_apply_script_runner_role_grants();` (`:54`) does not exist until V256 runs; `run()` aborts before creating `Secret/ui2-db-script-runner` (`:78`).
  - Running the deploy **before** `script_runner_db_login.py` also fails: `script-runner` is in default `TARGETS`, so after `ui2-service` runs V256 (starting with `UI2_SCRIPT_RUNNER_TOKEN_SHA256` unset because `secretKeyRef` `optional: true` is evaluated only at container creation), `module_deploy.py` deploys `ui2-script-runner`, which hangs in `ContainerCreating` (`secret "ui2-db-script-runner" not found`) until the 600 s rollout timeout aborts the release.
- **Fix:** Guard [script_runner_db_login.py:54](../../tools/delivery/script_runner_db_login.py#L54) with `SELECT CASE WHEN to_regprocedure('ui2_apply_script_runner_role_grants(text)') IS NOT NULL THEN ui2_apply_script_runner_role_grants() END;` (matching [10-configmap.yaml:83-84](../../deploy/ui2/10-configmap.yaml#L83-L84)) so `db-login` and `token` can be executed before first deploy; V256 line 239 then applies grants during migration and `ui2-service` starts with `UI2_SCRIPT_RUNNER_TOKEN_SHA256` populated.

#### P0-3: `nexus-cli` never sends `Origin` on non-`GET` requests — all state-changing `nexus-cli` commands (including `script-run` and in-pod script CLI calls) fail with HTTP `401 SESSION_INVALID`
- **Location:** [NexusSessionCli.java:648-652](../../ui2/cli/src/main/java/com/securityexpert/nexus/ui2/cli/NexusSessionCli.java#L648-L652), [GateChain.java:103-110](../../ui2/service/src/main/java/com/securityexpert/nexus/ui2/service/security/GateChain.java#L103-L110), [Containerfile:126](../../ui2/Containerfile#L126), [Containerfile.script-exec:49-53](../../ui2/Containerfile.script-exec#L49-L53).
- **Failure scenario:** `GateChain.evaluate` (`GateChain.java:107-109`) refuses every `POST`/`PUT`/`PATCH`/`DELETE` request without an `Origin` header (`401 SESSION_INVALID: request origin missing on a state-changing method`). `NexusSessionCli.call` sends `Cookie` and `X-CSRF-Token`, never `Origin`. Every `nexus-cli script-add`, `script-version-add`, `script-set`, `script-enable`, `script-disable`, `script-run`, and **every non-`GET` `nexus-cli` call inside a running script** fails with `401` against the live service (unit tests mocked around it at [ScriptSchedulerAndRunServiceTest.java:247](../../ui2/service/src/test/java/com/securityexpert/nexus/ui2/service/script/ScriptSchedulerAndRunServiceTest.java#L247)). Note that Java's `HttpClient` rejects `.header("Origin", ...)` unless `-Djdk.httpclient.allowRestrictedHeaders=origin` is set on the JVM, and `/app/nexus-cli` passes `-Duser.home=/app/home`, which is `0770` `0:0` on a read-only rootfs in `Containerfile.script-exec` (unreadable by uid `20185`).
- **Fix:** Add `-Djdk.httpclient.allowRestrictedHeaders=origin` to `/app/nexus-cli` (and `JDK_JAVA_OPTIONS` in [ScriptRunPodSpec.java:287](../../ui2/worker/src/main/java/com/securityexpert/nexus/ui2/worker/scriptrunner/ScriptRunPodSpec.java#L287)), switch `/app/nexus-cli` to `-Duser.home="${HOME:-/app/home}"`, send `Origin` derived from `session.baseUrl()` on non-`GET` calls in `NexusSessionCli`, add `script-output <runId>` to [ScriptCli.java](../../ui2/cli/src/main/java/com/securityexpert/nexus/ui2/cli/ScriptCli.java) for CLI parity, and test `NexusSessionCli` end-to-end through `RouteActionGate`.

### P1 — High-Severity Security & Reliability Findings

#### P1-4: `output_tail` (up to 4 KiB of stdout/stderr) is returned un-gated and un-audited to all roles on `SCRIPT_READ` routes
- **Location:** [ScriptExecutionController.java:312-343,482-486](../../ui2/service/src/main/java/com/securityexpert/nexus/ui2/service/api/ScriptExecutionController.java#L312-L343), [SecurityWebMvcConfig.java:426-427](../../ui2/service/src/main/java/com/securityexpert/nexus/ui2/service/security/SecurityWebMvcConfig.java#L426-L427), [ScriptExecutionPanel.tsx:1448-1473](../../ui2/frontend/src/screens/ScriptExecutionPanel.tsx#L1448-L1473).
- **Failure scenario:** Amendment 2026-11-18 (b) item 11 restricts script output to `role:operator`+ with a mandatory audit row, and [V256__script_execution_slice2.sql:63](../../ui2/service/src/main/resources/db/migration/V256__script_execution_slice2.sql#L63) classifies `output_tail` as Tier-2 sensitive operational text. Yet `GET /api/v2/scripts/{id}/runs` and `GET /api/v2/scripts/runs/{runId}` require only `SCRIPT_READ` (every authenticated role, zero audit) and return `output_tail` (up to 4 KiB — the **full** output of most scripts, up to 100 runs per call). A `role:viewer`, `backup_admin`, `onboarding_admin`, `role:viewer` script session (reading outputs of `role:operator` scripts), or operator avoiding `audit_script_output_download` reads operational output freely; `role:replay_viewer` also receives free-form operational text (and fields pre-masked in `ScriptExecutionController.java:430,484,487` are masked a second time by `PrivacyMaskingResponseBodyAdvice.java:123`). `ScriptExecutionPanel.tsx:1448` also renders `output_tail` when `canReadOutput` is `false`.
- **Fix:** Withhold `output_tail` (`null`) in `toRunMap` unless `!masked && can_read_output` (and either omit `output_tail` from un-audited list responses or record `audit_script_output_download` whenever `output_tail` is served on `getRun`); gate `ScriptExecutionPanel.tsx:1448` on `canReadOutput && !isMasked`; and avoid double-masking in `ScriptExecutionController` when `PrivacyMaskingResponseBodyAdvice` is active.

#### P1-5: Per-run `NetworkPolicy` allows internal cluster/registry/node/external-DB IPs via DNS resolution, device-egress correlation bypass, and unrestricted DNS tunneling when `egress = []`
- **Location:** [ScriptRunPodSpec.java:90-121,219-250](../../ui2/worker/src/main/java/com/securityexpert/nexus/ui2/worker/scriptrunner/ScriptRunPodSpec.java#L90-L121), [ScriptExecutionService.java:848-875,895-934](../../ui2/service/src/main/java/com/securityexpert/nexus/ui2/service/script/ScriptExecutionService.java#L848-L875), [56-service-internal.yaml:31-40](../../deploy/ui2/56-service-internal.yaml#L31-L40).
- **Failure scenario:**
  1. **Zero denylist on resolved egress IPs:** `resolveEgress` resolves `host` inside the broker via cluster DNS and emits `/32` or `/128` `ipBlock` rules for any returned IP. A declared internal name (or external hostname using DNS rebinding at run start) resolving to the **unauthenticated in-cluster container registry** (`registry.kube-system.svc.cluster.local`, insecure per `hosta_script_exec_image.py:49`), `ui2-configuration:8084`, `ui2-compliance:8085`, `ui2-service:9404` metrics (open to all pods in `56-service-internal.yaml:36-37`), kubelet `:10250`, HOST-A node IPs, link-local `169.254/16`, or an external PostgreSQL host (`UI2_DB_HOST:5432`, unprotected by pod `ui2-db-ingress`) grants direct TCP reachability — including pushing/overwriting container tags in the cluster registry.
  2. **Enrolled-device egress warning/ledger bypass:** Declaring a DNS name or hex IPv4-mapped IPv6 (`[::ffff:c000:0201]:22`) that resolves at run start to an enrolled device IPv4 (`192.0.2.1`) bypasses `validateAndCorrelateEgress` (stored string match only -> `egress_device_targets = []`) while `resolveEgress` (`InetAddress.getAllByName` converts IPv4-mapped IPv6 to `Inet4Address`) opens `/32` TCP egress to that firewall unrecorded.
  3. **DNS exfiltration when `egress = []`:** Rule 0 unconditionally opens UDP/TCP 53 to `kube-dns`, allowing scripts with `egress: []` to exfiltrate injected secrets via recursive DNS queries (`<hex>.attacker.tld`).
- **Fix:** Block loopback, link-local, multicast, unspecified, `KUBERNETES_SERVICE_HOST`, `UI2_DB_HOST`, node IPs, and cluster Pod/Service CIDRs in `resolveEgress` (logging a `[neXus]` stderr note). Correlate resolved `InetAddress`es against enrolled device endpoints so `script_run.egress_device_targets` is always accurate. When `egress` is empty, inject `ui2-service`'s IP via `podSpec.hostAliases` and omit the `kube-dns:53` rule so `egress: []` scripts have zero external DNS channel.

#### P1-6: Orphaned plaintext Kubernetes `Secret`s in etcd on broker crash/cancel, and HTTP `409 Conflict` run failures on lease-requeue retries
- **Location:** [ScriptRunJobExecutor.java:149-151,167-172,267-285](../../ui2/worker/src/main/java/com/securityexpert/nexus/ui2/worker/scriptrunner/ScriptRunJobExecutor.java#L167-L172), [ScriptRunPodSpec.java:123-134,184-213,358-370](../../ui2/worker/src/main/java/com/securityexpert/nexus/ui2/worker/scriptrunner/ScriptRunPodSpec.java#L123-L134), [InClusterKubernetesApi.java:146-156](../../ui2/worker/src/main/java/com/securityexpert/nexus/ui2/worker/scriptrunner/InClusterKubernetesApi.java#L146-L156).
- **Failure scenario:**
  1. `script-run-<id>-s<n>` Secrets contain the decrypted write-only `script_body`, plaintext `credentials.json`/`credentials.env`, and `session.json`, with **no `ownerReferences`** and **no TTL** (only `Job` has `ttlSecondsAfterFinished: 900`). If the broker crashes/restarts, if `delete` hits a transient error (`deleteAll` logs and swallows `IOException`), or if `JobReconciler` cancels/fails the job, those plaintext Secrets persist in etcd **forever** (and the broker lacks `secrets/list` to sweep them).
  2. `jobName(jobId)` excludes `leaseEpoch`. On a requeued run (epoch 2), `deleteAll` issues `DELETE` on the `Job` with asynchronous `propagationPolicy: "Background"` (`InClusterKubernetesApi.java:147`) and milliseconds later calls `create(JOB, sameJobName)` (`:172`) while the old `Job` still has `deletionTimestamp` set, failing with HTTP `409 Conflict` (`EXECUTION_ERROR:IOException`).
- **Fix:** Include the lease epoch in per-run object names (`script-run-<jobPrefix>-e<epoch>`). Create the `NetworkPolicy`, then create the `Job` and capture its `metadata.uid` from the `201 Created` response, then create the seed `Secret`s (and/or `NetworkPolicy`) with `ownerReferences` pointing to that `Job` UID (`seed` waits cleanly in `ContainerCreating` for the few ms until the `Secret`s exist). Kubernetes GC will then automatically delete every `Secret` when the `Job` is deleted or TTL-collected after 900 s, with zero extra RBAC verbs.

#### P1-7: Missing 30-day retention pruner for `script_output` violates the raw-evidence contract and fills the shared 10 GiB `ui2-report-store` PVC
- **Location:** [ScriptExecutionConfiguration.java:104-119](../../ui2/service/src/main/java/com/securityexpert/nexus/ui2/service/boot/ScriptExecutionConfiguration.java#L104-L119), [50-service-deployment.yaml:201-202](../../deploy/ui2/50-service-deployment.yaml#L201-L202), [37-report-store-pvc.yaml:18-19](../../deploy/ui2/37-report-store-pvc.yaml#L18-L19), [ArtefactClass.java:32-36](../../ui2/persistence/src/main/java/com/securityexpert/nexus/ui2/persistence/artefact/ArtefactClass.java#L32-L36).
- **Failure scenario:** Contract §2, §4.3, and `ArtefactClass.SCRIPT_OUTPUT` require 30-day retention for captured outputs, and `UI2_SCRIPT_STORE_ROOT` shares the 10 GiB `ui2-report-store` PVC with Reports R1. Because `ScriptRunDispatchService.finish` writes directly to `FileArtefactStore` without `backup_artefact` rows, neither `RetentionPruningService` nor any service task ever deletes expired `script_output` files or clears `script_run.output_tail`. Frequent cron scripts (e.g. `* * * * *` producing 512 KiB/run $\approx 720\text{ MiB/day}$) permanently exhaust `ui2-report-store`, breaking both Script Execution and Reports R1.
- **Fix:** Add a scheduled retention task in `ui2-service` that prunes `script_output` files under `UI2_SCRIPT_STORE_ROOT` and clears `output_artefact_ref`, `output_key_id`, `output_wrapped_data_key`, and `output_tail` on `script_run` rows older than 30 days.

### P2 — Defense-in-Depth, DoS Hardening & Lifecycle Consistency

#### P2-8: `runNow` executes disabled scripts (`enabled = false`) and has no per-script in-flight / rate cap (queue starvation & recursive `role:operator` self-runs)
- **Location:** [ScriptExecutionService.java:546-591](../../ui2/service/src/main/java/com/securityexpert/nexus/ui2/service/script/ScriptExecutionService.java#L546-L591), [JooqScriptRepository.java:249-309](../../ui2/persistence/src/main/java/com/securityexpert/nexus/ui2/persistence/script/JooqScriptRepository.java#L249-L309), [ScriptExecutionPanel.tsx:2468-2475](../../ui2/frontend/src/screens/ScriptExecutionPanel.tsx#L2468-L2475).
- **Failure scenario:** Disabling a compromised or broken script (`POST .../disable`) only stops cron fires; `runNow` ignores `script.enabled()`, allowing any `role:operator` (or a running `role:operator` script session) to keep executing it. Moreover, `idempotencyKey = "script_run:" + jobId` is unique per call with no per-script active-run limit, so a `role:operator` script calling `/api/v2/scripts/<id>/run` in a loop can enqueue thousands of 3600 s jobs and stall the single-threaded broker for days.
- **Fix:** Refuse `runNow` when `!script.enabled()` (at least for non-`security_admin` callers), block `script_session:*` from `SCRIPT_RUN` (or cap recursion), and enforce at most one active (`REQUESTED`/`CLAIMED`/`EXECUTING`) manual run per `script_id`.

#### P2-9: Execution pod lacks `ephemeral-storage` and `ulimit -u` PID limits, and writes plaintext seed secrets to disk-backed `emptyDir`
- **Location:** [ScriptRunPodSpec.java:51-61,314-353](../../ui2/worker/src/main/java/com/securityexpert/nexus/ui2/worker/scriptrunner/ScriptRunPodSpec.java#L314-L353).
- **Failure scenario:** (1) Without `resources.limits.ephemeral-storage`, a script flooding stdout/stderr (`yes ...`) for 3600 s writes tens of GiBs into `/var/log/pods` on HOST-A's root filesystem (the broker only caps its final *read* at 4 MiB), triggering node `DiskPressure`. (2) Without `ulimit -u`, a fork bomb inside `script` can exhaust node PIDs. (3) `/scratch` `emptyDir` omits `"medium": "Memory"`, writing decrypted write-only script bodies, `credentials.json`, `credentials.env`, and `session.json` to HOST-A's disk journal.
- **Fix:** Set `"ephemeral-storage": "1Gi"` in `script` container `limits`; add `ulimit -Hu 256 -Su 256` to `LAUNCHER` before `"$@"`; and mount a `"medium": "Memory"` `emptyDir` (e.g. `32Mi`) for seed secrets/scripts.

#### P2-10: Job cancellation / reconciliation desynchronizes `jobs.state` vs `script_run.state`, and DB heartbeat exceptions do not kill runs past `lease_expires_at`
- **Location:** [ScriptRunJobExecutor.java:176-188,305-307](../../ui2/worker/src/main/java/com/securityexpert/nexus/ui2/worker/scriptrunner/ScriptRunJobExecutor.java#L176-L188), [ScriptRunnerClaimLoop.java:95-106](../../ui2/worker/src/main/java/com/securityexpert/nexus/ui2/worker/scriptrunner/ScriptRunnerClaimLoop.java#L95-L106), [V256__script_execution_slice2.sql:56-59](../../ui2/service/src/main/resources/db/migration/V256__script_execution_slice2.sql#L56-L59).
- **Failure scenario:** (1) Cancelling a `script_run` on the Jobs screen sets `jobs.cancel_requested = true` (or `CANCELLED`): `ScriptRunJobExecutor` never polls `leases.cancellationRequested`, records `script_run.state = 'COMPLETED'`, and then `leases.transitionState(..., COMPLETED)` silently affects 0 rows ([JooqJobLeaseDao.java:235](../../ui2/persistence/src/main/java/com/securityexpert/nexus/ui2/persistence/jobrecords/JooqJobLeaseDao.java#L235)), leaving `jobs.state = 'CANCELLED'` vs `script_run.state = 'COMPLETED'` (or leaving `script_run` stuck in `REQUESTED`/`RUNNING` with an unrevoked session if cancelled before claim or failed by `JobReconciler`). (2) In `ScriptRunnerClaimLoop.java:103-105`, JDBC exceptions during a >60 s DB partition are logged without setting `leaseLost = true`, letting the pod run past `lease_expires_at`.
- **Fix:** Track `leaseValidUntil` in `ScriptRunnerClaimLoop` and set `leaseLost.set(true)` once `clock.instant()` passes `leaseValidUntil` on heartbeat errors; poll `leases.cancellationRequested` in `runPod`; and add an `AFTER UPDATE OF state ON jobs` trigger closing open `script_run` rows when `jobs.state` enters `CANCELLED`/`FAILED`/`OUTCOME_UNKNOWN`.

#### P2-11: Broker Kubernetes RBAC (`jobs/create` + `pods/log/get`) and DB role (`ui2_script_runner`) blast radius under broker compromise
- **Location:** [61-script-runner-deployment.yaml:40-61](../../deploy/ui2/61-script-runner-deployment.yaml#L40-L61), [V256__script_execution_slice2.sql:200-234](../../ui2/service/src/main/resources/db/migration/V256__script_execution_slice2.sql#L200-L234).
- **Failure scenario:** While the broker runs no user code, (1) `batch/jobs` `create` + `pods/log` `get` in `ui2` allows a compromised broker JVM to spawn a Job mounting `ui2-artefact-store-key`/`ui2-credential-store-key`/`ui2-db` and read them from pod logs (defeating the `secrets` `get` restriction noted on `:38-39`), or `delete` `ui2-db-ingress` / `ui2-script-run-default-deny`; `list`/`watch` on `jobs` and `watch` on `pods` are also unused. (2) `ui2_script_runner` has un-scoped `UPDATE`/`DELETE` across all rows of `jobs`, `failover_run`, `failover_resume`, `pan_config_sync`, `endpoint_admission`, and `runtime_task_lease`.
- **Fix:** Remove unused `list`/`watch` verbs; add a Kubernetes `ValidatingAdmissionPolicy` restricting `system:serviceaccount:ui2:ui2-script-runner` Jobs/Secrets/NetworkPolicies to `script-run-*`, `serviceAccountName: ui2-script-run`, and no non-`script-run-*` Secrets/PVCs/`hostPath`; and add RLS on `jobs` (`capability_id = 'script_run'`) plus `SECURITY DEFINER` on `jobs.state` triggers to drop the `failover_*` grants.

#### P2-12: Output masking misses 76-column MIME Base64 (GNU `base64` default) and `LAUNCHER` leaks raw container-log `fd 3` into child scripts
- **Location:** [ScriptOutputMasking.java:149-156](../../ui2/platform-core/src/main/java/com/securityexpert/nexus/ui2/platform/ScriptOutputMasking.java#L149-L156), [ScriptRunPodSpec.java:56-57](../../ui2/worker/src/main/java/com/securityexpert/nexus/ui2/worker/scriptrunner/ScriptRunPodSpec.java#L56-L57).
- **Failure scenario:** (1) On UBI 9, `base64` wraps output at 76 columns (`\n`) by default; `Base64.getEncoder()` only generates single-line Base64, so any secret $\ge 57$ bytes (including the 64-char `sessionCookie`, SSH keys, or long tokens) piped through `base64` escapes masking. (2) `exec 3>&1` in `LAUNCHER` leaves raw container stdout `fd 3` open in `"$@"`, letting a script forge `O|`/`E|` stream tags or interleave mid-line writes (`>&3`).
- **Fix:** Add `Base64.getMimeEncoder(76, "\n".getBytes())` (and `\r\n`) variants in `ScriptOutputMasking.addForms`, and close `fd 3` for the child in `LAUNCHER` (`"$@" 3>&- 2> >(...)`).

#### P2-13: Snapshot rollback (`release_snapshot.py` / `module_deploy.py --rollback`) does not preserve `script_runner` self-ownership or restore `UI2_SCRIPT_EXEC_IMAGE`
- **Location:** [release_snapshot.py:323,353-357,366-391](../../tools/delivery/release_snapshot.py#L323-L391), [module_deploy.py:547-548,599-601](../../tools/delivery/module_deploy.py#L547-L601).
- **Failure scenario:** `KEEP_ON_ROLLBACK` omits `ui2-script-runner`, so full rollback sets `script_runner.effective_owner = 'general'` (which has no `script_run` executor), and `split_rollback` runs `kubectl set image` on the broker container only without restoring the snapshot's `UI2_SCRIPT_EXEC_IMAGE`.
- **Fix:** Add `"ui2-script-runner": "script_runner"` to `KEEP_ON_ROLLBACK` and restore `UI2_SCRIPT_EXEC_IMAGE` from the snapshot manifest on rollback.
