### 2.1 Check Point Packet Order: Evaluating NAT Before Access Control Rulebase
- **Where**: [`PATH_ANALYSIS_DESIGN_FABLE.md:213-216`](file:///Users/OzanDur/Codo/wt-pathanalysis-design/docs/design/PATH_ANALYSIS_DESIGN_FABLE.md#L213-L216).
- **The error**: Fable executes **NAT evaluation (Step 2) → Route Lookup (Step 3) → Security Rulebase (Step 4)**.
- **Why this produces wrong verdicts**:
  1. In Check Point R80.x/R81.x FireWall-1 inspection, the **Access Control Rulebase is evaluated on the pre-NAT packet header before NAT rules are applied** (even when the global property `translate_destination_on_client_side` is enabled so that destination NAT affects routing/egress interface selection, a packet dropped by the Access Control rulebase is dropped immediately—NAT never fires). Under Fable's order, if Step 3 (Route Lookup on post-DNAT destination) hits `NO_ROUTE`, `DROPPED_BY_ROUTE`, or `EXITS_KNOWN_TOPOLOGY`, or if Step 2 hits an unresolvable NAT rule, the hop terminates or obscures the fact that the firewall's Access Control policy explicitly **DENIED** the packet at that gateway.
  2. Fable claims (`:143`): *"CP rules are address-based, `PolicyLookup` needs install-on only."* This is false whenever a Check Point Access Control rule uses **Security Zone (`security-zone`) objects** in its Source or Destination column (currently classified in [`CpObjectTypes.java:12`](file:///Users/OzanDur/Codo/wt-pathanalysis-design/ui2/platform-core/src/main/java/com/securityexpert/nexus/ui2/policy/CpObjectTypes.java#L12) under `DYNAMIC_TYPES`). When `translate_destination_on_client_side` is active, a destination `security-zone` object is matched against the **post-DNAT egress interface's zone**.

### 2.5 Asymmetric Return Path Across Stateful Firewalls Treated as a Non-Blocking Warning
- **Where**: [`PATH_ANALYSIS_DESIGN_FABLE.md:241`](file:///Users/OzanDur/Codo/wt-pathanalysis-design/docs/design/PATH_ANALYSIS_DESIGN_FABLE.md#L241).

- **Why this produces a false `ALLOWED`**: This has stateful vs. stateless networking backwards. Stateless L3 routers (Phase D) forward asymmetric return traffic without issue unless stateless ACLs block it. Returning `ALLOWED` with a mere warning when the reverse path bypasses a forward stateful firewall (or NAT hop) is a severe **false `ALLOWED`**.

### 7.1 `aiview` Query Input Catch-22 in Fable's Design (Breaks `aiview`-Only Operation)
- **Concern in Fable (`PATH_ANALYSIS_DESIGN_FABLE.md:190, 272-289`)**:

When an `aiview` user enters a masked IP (`240.x.y.z`) from the inventory/policy screen, the engine searches the unmasked database (`10.x.y.z`) for `240.x.y.z` and returns `NO_INGRESS_CANDIDATE`!
