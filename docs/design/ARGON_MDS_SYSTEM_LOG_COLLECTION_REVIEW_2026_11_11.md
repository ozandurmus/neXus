- **[BLOCKER] `T-5` and `T-4` misunderstand GNU `grep -m <NUM>` semantics — `T-5` is unbounded across rotated files and reads oldest rotations first ([MDS_SYSTEM_LOG_COLLECTION_DESIGN_2026_11_11.md](file:///Users/OzanDur/Codo/nexus-mdssyslog-1111/docs/design/MDS_SYSTEM_LOG_COLLECTION_DESIGN_2026_11_11.md#L335-L336), [§9 Note](file:///Users/OzanDur/Codo/nexus-mdssyslog-1111/docs/design/MDS_SYSTEM_LOG_COLLECTION_DESIGN_2026_11_11.md#L346)):**
  - In GNU `grep`, `-m 100` stops after 100 matches **per input file**, not 100 matches total across all files.
  - In `T-5`, `$MDS_FWDIR/log/cpm.elg* $RTDIR/log/solr.log* $RTDIR/log/RFL.log*` expands across ~60+ rotated files (~1.2+ GB on disk per §8 MC-1 note). `grep -m 100` will scan all ~60+ files in lexicographical order (`cpm.elg`, `cpm.elg.0`, `cpm.elg.1`, `cpm.elg.10`..`cpm.elg.59`), can emit up to `100 * N_files` (>6,000) lines from weeks-old rotations, exceed the 128 KiB `maxBytes` cap (`OUTPUT_LIMIT_EXCEEDED` -> `UNKNOWN`), and cause heavy disk I/O during post-crash triage.
  - In `T-4`, `/var/log/messages.1 /var/log/messages` only checks `.1` and live `messages`, yet §5.1 notes `/var/log/messages` rotated every 15–30 minutes during the fault (so the 02:25 crash is in `messages.2`..`messages.N` by morning), and if `messages.1` does not exist on a clean box, `grep` prints a stderr error and exits `2`.
  - **Fix:** Scope `T-5` to the active file and `.0`/`.1` siblings only (not `*`) and pipe to `| tail -n 100`; in `T-4`, pass `-s` (`--no-messages` for missing `.1`) and pipe to `| tail -n 200`.
- **[MAJOR] `MX-2` has a shell precedence bug (`&&` vs `;`) and its `loadavg` diff cannot measure `mdsenv` fork cost ([MDS_SYSTEM_LOG_COLLECTION_DESIGN_2026_11_11.md](file:///Users/OzanDur/Codo/nexus-mdssyslog-1111/docs/design/MDS_SYSTEM_LOG_COLLECTION_DESIGN_2026_11_11.md#L424)):**
  - Literal: `bash -lc 'cat /proc/loadavg; mdsenv <DS>&& echo "FWDIR=$FWDIR"; echo "CPDIR=$CPDIR"; cat /proc/loadavg'`
  - Because `&&` binds only to `echo "FWDIR=$FWDIR"`, if `mdsenv <DS>` fails, `; echo "CPDIR=$CPDIR"` still executes in the MDS-level shell context and prints the MDS-level `$CPDIR` as if it were the Domain's `$CPDIR`. Must chain with `&&`: `mdsenv <DS> && echo "FWDIR=$FWDIR" && echo "CPDIR=$CPDIR"`.
  - Furthermore, the 4th field of `/proc/loadavg` (`running/total`) is the instantaneous live task count. By the time `mdsenv <DS>` finishes, all helper processes it forked have already exited, so comparing `running/total` before and after `mdsenv` measures `0`. To measure how many forks `mdsenv` caused, read the 5th field of `/proc/loadavg` (`last_pid`) or `grep ^processes /proc/stat` (cumulative kernel forks since boot) before and after `mdsenv`.
