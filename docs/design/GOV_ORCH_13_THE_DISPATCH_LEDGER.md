# GOV.ORCH.13 — The dispatch ledger

## Status

**FROZEN — PRODUCT OWNER DIRECTIVE, 2026-09-14.** The Product Owner asked
that every dispatch be recorded and kept: how long it took, which provider
and model ran it, how many tokens it processed, what it cost, and whether it
could have been done better. Extends
`GOV_ORCH_4_WORKBENCH_OBSERVABILITY_TOKENS_AND_STUCK_DETECTION.md` §3
(FROZEN, not edited in place), which measures a *running* movement; this
record is what survives it.

## 1. Why

Token and cost figures live in a per-movement cache under the state
directory and are lost with it; wall-clock duration is nowhere; the
retrospective the Product Owner asks for after every dispatch exists only in
chat. Three days of dispatches have already produced numbers that cannot be
compared across providers, and the first cross-provider comparison had to be
reconstructed by hand.

## 2. The decision

- **DL-1. One ledger, in the repository:** `project/DISPATCH_LEDGER.md`,
  regenerated by a script from the orchestrator's own records, never hand
  written. It is data the loop produces, so it is not subject to the
  documentation diet of GOV.ORCH.6.
- **DL-2. One row per dispatch attempt, not per movement.** A movement
  relaunched after a failure has several attempts; each is its own row with
  its own duration, tokens and cost. Collapsing them hides exactly the waste
  the ledger exists to show. Where the state directory no longer holds an
  earlier attempt, the row says so rather than omitting it.
- **DL-3. Each row carries:** movement, attempt, the date it started,
  provider, model requested, effort, wall-clock minutes, turns, total
  tokens, cache hit ratio, cost with its `cost_source`, the budget ceiling,
  the outcome (`done` / `failed` with its reason), and the pull request
  number when there is one.
- **DL-4. Cost honesty.** A subscription-billed provider's figure is a
  comparable, never billed spend (GOV.ORCH.4-A CU-4). The ledger totals
  metered and subscription costs **separately** and labels both. A row
  whose cost is unavailable shows a dash and is counted nowhere.
- **DL-5. The assessment column is human and is preserved.** One line per
  row: what to do differently. The renderer never overwrites an existing
  assessment; it only fills empty ones with a placeholder. This is the
  Product Owner's standing retrospective, written down instead of said.
- **DL-6. Derived, never authored.** Duration comes from the record's own
  start and last-activity timestamps; a negative or absent duration is
  printed as unknown rather than computed into a number, because a relaunch
  that reuses a movement id has produced exactly that.

## 3. What this is not

Not an invoice, not a budget authority, not an input to any gate. Nothing
reads the ledger to decide anything; it exists so the Product Owner can see
where the money and the hours went and change the next packet.
