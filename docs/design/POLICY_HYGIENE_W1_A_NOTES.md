# Policy hygiene W1-A implementation notes

Status: Implementation reference; authority is PO_DECISION_RECORD_2026_10_09_NSPM_WAVE1.md.

Analysis uses stored snapshots only. Findings describe collected management intent, not effective device behavior. Disabled rules cannot cover later rules. Rules are evaluated in stored order within each section; CP inline sections and PAN pre/post/device-group sections remain separate. No claim is made about cross-section shadowing or partial overlaps. A covering rule has fully resolved selectors and a terminal action; same action is redundant (MEDIUM), different action is conflict (HIGH).

IPv4 hosts, CIDRs, ranges, recursive static groups, TCP/UDP destination port ranges and ANY are normalized once with memoized object expansions. Negation, unresolved objects, cycles, IPv6, application-specific semantics, application-default, source ports, identity conditions, nontrivial schedules, NAT, nonterminal actions and unsupported match extensions yield UNKNOWN. Zone coverage is proven only for ANY or identical selector sets; install-on requires resolved, identical selectors. Missing PAN zone or CP install-on evidence is UNKNOWN. Unsupported preceding rules and incomplete snapshot collections prevent a clean negative conclusion. This deliberately favors missing a finding over a false shadow claim. CP sections do not carry an opaque common layer identity; labels are never used to join them.

The deterministic work budget is 250,000 units across object visits, expanded intervals and candidate comparisons. Candidates are pruned by section and supported terminal action. The remainder reports UNKNOWN (analysis budget). Results are computed lazily and cached for 30 seconds, at most four snapshots. Snapshot content equality invalidates replaced evidence under the same policy ID; threshold changes invalidate the result. The clock is an explicit engine input. Existing breadth/schedule traversals also have finite recursion and visit limits.

Permissiveness reuses PolicyRuleMetrics: each distinct Any source/destination/service/application contributes 2 points; each Large CIDR selector (IPv4 prefix <=16) and Broad service range (end minus start >=1024) contributes 1. Score 0 is Low, 1–3 Medium, >=4 High; incomplete evidence makes the verdict Unknown irrespective of score. Reasons and score appear inline. Broad findings are MEDIUM, except an accepting rule with all four selectors ANY is HIGH. Disabled, unused and expired/expiring findings are LOW. UNKNOWN findings are LOW information gaps, not evidence of a defect.

Unused defaults to 90 days, configurable from 1 to 36,500. Old last-hit evidence is measured at counter collection time, not today's wall clock (stale snapshots cannot invent inactivity). Missing target counts or invalid timestamps yield UNKNOWN. HitCounts has no counter-reset/window-start field. FirstHit is never treated as a window start. Rule creation provides only an upper bound: zero hits on a younger rule are UNKNOWN; other zero-hit findings explicitly retain the unknown-window limitation. Counter source and collection timestamp accompany every finding and CSV row.

Read APIs use POLICY_READ, no-store and the existing PolicyResponse AIView projection. CSV applies that projection before formatting names and counter provenance and escapes spreadsheet formulas. Counts are distinct rules per class; the filtered list is paginated at 200 rules, while CSV includes all matching findings. Rule detail links fetch by opaque rule ID independently of the current Rules page.
