Storage/security note
---------------------
Large configuration payloads are now stored once by SHA-256 under data/artifacts/config/sha256.
Per-run history under data/configs contains metadata/reference files only. Existing legacy data
is not deleted automatically. --storage-deduplicate is dry-run unless --apply is explicitly used.
The apply manifest is written before destructive migration work and records how a removed legacy
payload can be reconstructed from its immutable content-addressed object.

Check Point scope
-----------------
A4.3.2 makes the storage layer vendor-neutral and validates future Check Point Gaia/Clish text
artifacts against the same store. It deliberately does NOT change CP collection/authentication/
parser behavior in this phase; those changes remain part of the Check Point configuration phase.
